# 公开搜索基线与原生修复记录（2026-09-26）

历史实验归档。当前使用方式见[公开信息搜索](../../PUBLIC_SEARCH.md)，后续目标见[修复规格](../../../.scratch/public-search-repair/spec.md)。下述产物路径按仓库根目录解释。

2026-09-26 检查：本机为 M4 Pro、14 核、24 GB 内存。用户将游戏更新到 0.111.0 后，仓库副本的原生引擎构建成功（0 错误、3 个既有可空性警告）。使用临时目录内的 .NET 9.0.7，原生引擎已能创建 A0 对局并返回 `training_ready=true` 的公开决策帧，启动日志无 `[ERROR]`。

首轮双 worker 烟测在 19.00 秒内完成 8 次尝试，全部战败，6 局死于第一幕 Boss。8 条失败前缀均在新原生进程中无状态哈希偏差地重放到战败。复盘发现必然跳过未打开宝箱的规则错误，已修复；另补齐清洗器遗漏的公开 HP 损失、力量等 DynamicVars 白名单，不改变轨迹 schema，也不保留隐藏字段。

修复后的第一轮全线程测试在 81.98 秒内完成 100 次尝试，全部战败，其中 27 局进入第二幕，无协议错误。该版本尚只展开基础攻击/防御，不能据其运行速度声称达成成功轨迹产出目标。结果保存在 `combat_solver_cli/artifacts/public-smoke-001/summary.json` 和 `combat_solver_cli/artifacts/public-a0-native-001/summary.json`。这些是开发阶段随机种子烟测，不是固定条件的算法优劣实验。

扩展当回合卡牌组合后的第二轮在 145.53 秒停止，已启动 167 次尝试：153 次战败、13 次协调停止、1 次原生空引用错误，无验收成功。已结束战败中 92 局在第一幕、58 局在第二幕、3 局在第三幕；另一次第三幕对局记录了原生错误。错误触发批次停止，没有降级当作战败或忽略验收。记录见 `combat_solver_cli/artifacts/public-a0-native-002/summary.json`。随后修复补能牌在根候选受限时失去机会价值的回归；不能把该旧测试直接视为修复后性能。

第三轮在 193.60 秒内启动 271 次尝试：257 次战败、13 次协调停止、1 次终局协议错误，仍无验收成功。两类真实引擎错误分别定位为 Soul Nexus 死亡动画访问不存在的 Godot 房间，以及异步死亡结算期间 `IsGameOver` 先于终局确认可见。前者仅将表现层房间访问改为可空访问，保留死亡逻辑；后者最多等待 3 秒确认真实终局，超时仍报错，并保证胜利里程碑先入队再发布终局标志。没有将异常视为成功，也没有放宽三幕 Boss 与独立重放验收。

第四轮在 27.72 秒后因 `candidate_no_longer_legal` 停止：最后一只敌人死亡后的异步结算曾发布没有敌人的战斗帧，随后其中的结束回合候选失效。协议现在将这类过渡状态保留为等待，并在发布战斗帧前再次检查能否行动；没有放宽执行时的合法性检查。修复后重放该局前 266 条有效动作，全部状态哈希一致，并直接进入奖励阶段。旧故障帧中的额外动作不再存在，也未强制重放。

终局时序故障的另一条 280 动作前缀已在新引擎连续重放三次，状态哈希全部匹配，均确认正常战败，无原生错误。以上只验证具体故障修复，不证明所有游戏交互均已覆盖。

第五轮使用上述修复，14 个 worker、300 秒预算，实际在 301.68 秒结束：428 次尝试中 414 次战败、14 次预算停止，零协议错误，零验收成功，平均成功轨迹成本为 `null`。记录见 `combat_solver_cli/artifacts/public-a0-native-005/summary.json`。期间有短暂的独立回归负载，因此不作为独占机器吞吐基准；但没有产出成功轨迹的结论明确。当前规则教师未达到使用目标，不能以尝试次数或测试通过代替通关能力验收。

最终验证：25 项 Python 搜索与采集行为测试通过；原生协议、异步操作与 Soul Nexus 回归中 36 项通过，旧“仅接受 A10”的断言更新为真实协议启动下的 A0/A10 两端点检查后，两项均通过。五角色各 5 局随机策略回归全部正常结束，无错误，均未获胜。原生构建仍有 3 个既有可空性警告。残余异步竞态仍由执行时合法性检查拒绝，不保证已经覆盖所有游戏交互。
