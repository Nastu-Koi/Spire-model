# 系统架构

为《杀戮尖塔 2》训练一个只看玩家公开信息、覆盖整局的策略，目标是**五角色 A0 平均整局通关率**。主模型用公开状态的实体编码器、带关系偏置的 Full Attention 全局层和无状态决策头，做包括战斗在内的全部决策；普通宝箱、指定单选事件和水晶球格子由固定控制器处理。术语见 [CONTEXT](../CONTEXT.md)，用法见 [README](../README.md)，各模块的实现见 [implementation/](implementation/)。本文写目标设计；实现进度与实测记录在本地 `.scratch/joint-training/`。

## 设计原则

- **先小后大**。约 20M 的小配置（`configs/rtxpro6000.json`）验证训练路线，路线的每一步在 20M 上过门槛后才转向约 200M（`configs/rtxpro6000-200m.json`）。目标规模取 200M 而不是 1B：示范每轮约五百万宏动作，行为克隆撑不起十亿参数，1B 的采样前向也让迭代成本不可接受。
- **只用行动前公开信息**。保留完整合法动作集合、无序牌堆的重复数量与排列不变性，以及公开且有意义的顺序。
- **每个决策都给完整公开状态**，局内局外都带地图；吞吐问题从编码侧解决，不裁剪输入。
- **训练信号来自同一起点的多条续局**。整局只有一个 ±1，三百多个宏动作共用它，单个选择的价值被整局噪声淹没。对局按幕切成几段，每幕从幕开头的存档续打几条，组内平均回报作基线，后一幕的组均值作前一幕的回报；不训练价值模型。局内局外的决策在同一个批里一起更新，因为局外选择的价值取决于战斗能否用好它，战斗的价值也只通过战后的局外状态体现。
- **示范只用于起步**。行为克隆从摘要重建的人类示范和求解器战斗起步；起步之后策略只从自己的对局学。
- **效果只认配对评估**。结论来自固定种子、五角色均衡的 500 局 greedy 配对比较；训练采样的胜率不是证据。

## 数据流

```
Spire Codex 摘要 ─ spire_codex_data（锚点 + 求解器）─ demos 导入 ─┐
                                                                 ├─ BC 起步（两段）─ 检查点
                                                                 │
检查点 ─ play 幕组采样（第一幕从开局，之后每波从上一波的存档续打：幕开头或 Boss 入场）─ 各波的段
各波的段 ─ 回报沿链回传 ─ 组内优势（共享前缀的分叉树 + 组内基线）─ learn 一遍更新 ─ 新检查点

```

## 输入与公开信息

`decision_frame` 由 `contract`、`routing`、`public`、`legal.candidates` 组成。模型只用行动前公开信息；seed、内部随机数、隐藏牌序、候选编号和对象地址不作特征，引用只用来建立实体关系、把动作映射回游戏操作。

- 公开实体和完整动作库各成为 token（地图除外，见“地图压缩”）。没有公开顺序的牌堆保留完整多重集合，同名牌不合并，打包下标不加位置编码；效果执行顺序、公开槽位等有意义的顺序另行表达。
- 字段编码：每个字段的身份是符号 embedding 加字段名 embedding；数值由以字段身份为输入的 MLP 编码后与身份相加（数值必须与字段绑定，否则 `hp=12, block=40` 与 `hp=40, block=12` 相同）。数值特征为 `value/100`、带符号 `log1p`、`known`、`applicable`、`is_numeric` 和 8 组周期 4 到 2048 的正余弦。字段求和后按字段数平方根归一化，未知值不等于零。
- 全局标记（第 0 个 token）带阶段与多选进度；已选实体带 `selected`，顺序有意义时带 `selected_order`。
- **公开历史**由系统维护并显式输入，不加循环状态：战斗内保留上一回合敌人意图、抽牌堆里公开已知的位置、药水掉落概率；局外保留问号房间概率和药水掉落概率。无头与 Steam 编译同一份状态机（`public_history/`）；中途接管或缺前缀时为 unknown，不从隐藏存档补值。
- 契约：`public-state-v6`、`public-history-v1`、`public-encoding-v3`。公开历史不兼容的检查点不能用于当前输入。

## 局部程序与规则文本

一个 token 可以带一段局部程序（节点与类型化关系），经局部注意力层编码后取根节点加池化汇入该 token。来源有三种：引擎的效果程序；规则文本（引擎标为 `OPAQUE_RULE` 的卡牌、遗物、药水、能力、充能球、事件选项，程序取自游戏自己的描述文本）；地图程序。解析不依赖权重，按内容缓存；批内相同程序只编码一次，按节点数分组。

规则文本让内容之间共享语义：公开对局里大部分内容只出现几次，只靠内容 ID 学不出含义，而描述文本按定义是完整的公开语义。模板按实体公开值渲染，值不公开的变量保留为 unknown；程序是根节点加按顺序的词节点，顺序只在相邻、前后关系里。选项文本里的变量分数值（`amount`）和内容名（`names`，指向目录里已有的内容符号）。规则文本属于输入，摘要写入检查点，不一致即拒绝。规则编码器与主策略都从随机权重开始，不用预训练语言模型。

## 地图压缩

地图节点里只保留当前节点、**地图前沿**和仍被引用的节点。每个前沿节点带一段地图程序：从它出发可达的全部节点（房间类型、楼层、列、相对深度，Boss 节点带遭遇），节点对之间的关系为自身、直接连接、间接可达、自由通行的单步、不可达。整张地图约 60 个节点、会在每个阶段占去一半以上的 token，而决策需要的正是“选这个节点之后会遇到什么”。自由通行成立时后继加上下一层全部节点，只靠自由通行的一步单独成一种关系。

## 全局骨干

全局层全部是双向 Full Attention，SwiGLU FFN。实体之间的类型化关系是加性注意力偏置：每种关系对每个头一个可学习标量，每层一张表（各层可以沿不同关系聚合）。没有偏置时，两个字段相同、只有一个带易伤的敌人，“打 A”和“打 B”在输入端相同；有了偏置，动作沿 `target` 找到目标，目标沿反向 `owner` 找到能力。

结构只有一种（`architecture_version` 3）：query/key 归一化、残差输出投影按 1/√(2L) 缩小、字段间注意力、决策头的 query/key 归一化、线性层无偏置、RMSNorm。20M 与 200M 是同一结构的两个尺寸（宽 256 与 768、24 层）；其它结构版本的检查点按版本拒绝载入。

## 冻结的名称表

字段符号、字段名、关系角色三张表随检查点冻结。登记的名称各占一行；冻结后才出现的名称哈希到空行，报告为 `unregistered_names`；未登记的符号共用 `<unknown>` 并带字段名前缀报告。冻结时登记的内容来自引擎静态目录和表示层的完整枚举，不依赖碰巧见过哪些帧；新增一种引擎导出的名称时登记是必须的一步。

## 决策头

全局标记的最终状态 `h₀` 作查询：动作分数 = `query(h₀) · key(h_action) / √d`，非法动作屏蔽。每个决策独立编码、不保留状态；多选逐步进行，进度来自输入。策略网络没有价值头。

## 环境步骤与控制分工

| 决策 | 由谁做 |
| --- | --- |
| 普通宝箱（含问号房间里的） | 控制器：开箱 → 领取遗物 → 离开 |
| 只有一个可用事件选项、其余只能丢药 | 控制器推进该选项 |
| 水晶球格子与工具 | 公开几何规划器（不读隐藏布局与随机数） |
| 战后与事件领奖、水晶球支付、遗物触发的选牌、商店、战斗 | 主策略 |

控制器步骤记为环境操作证据，不产生策略损失、不计入样本数与权重；无头、Steam、示范导入、训练共用 `main/env/control.py` 的同一套判断（`public-control-v1`）。

候选只包含有结果的动作：免费查看（已生成的卡牌奖励、商店货架、地图）由适配层展开进观测；无结果的返回不是候选；打开即产生结果的（开箱、重掷）保留为候选，内容揭示后才进观测。非战斗的可取消选择（锻造、商店删牌、移除奖励）**打开即承诺**，不发布 `CANCEL`，避免“打开 → 取消”的无结果循环。

## 训练路线

1. **BC 起步**。示范来自摘要锚点（见 [demos](implementation/demos.md)）：局外是人类在重建状态上的选择，战斗是求解器在重建入场状态上打出的动作。分两段：第一段拟合 A0–A10 全部示范；第二段严格续训、只拟合 A10，战斗换成按更大预算另求的 A10 战斗。第二段每轮留检查点，选 A0 评估最好的一轮作起点。
2. **幕组迭代**。每次迭代：
   1. 当前策略按采样温度打一轮幕组：每个种子从开局打 n 条到第二幕开头（写幕开头存档），每份第二幕存档续打 m 条到第三幕开头，每份第三幕存档续打 m 条到终局；可以再在某几幕的 Boss 入场切一级（见下）；
   2. 每一波按组算优势（见下）；
   3. 一遍更新：每个逻辑批按份额从各波取样本，裁剪目标；
   4. 每几次迭代 500 局评估。
3. **200M**。幕组迭代在 20M 上过门槛后，200M 从随机初始化做同样两段的 BC 起步，之后用自己的采样走第 2 步。不迁移 20M 权重：宽度扩展不保函数，20M 的作用是验证路线。

### 幕组的回报与优势

- **回报**。最后一波是终局 ±1；之前每一波的段若到达边界幕，回报是下一波从它的存档续打的组的平均回报，一波波往前传。前一幕的回报因此是“从这里继续，当前策略最终通关的比例”的蒙特卡洛估计，而不是“到达下一幕”：后者是截断奖励，会奖励多休息、留药水这类只顾眼前的做法。
- **分幕的理由**。三幕各自开局，组内各段共享更长的起点、视野更短；后一幕的组均值把这一幕之后的随机性平均掉一部分，所以前一幕的回报方差小于整局 ±1。
- **优势**。同一组的段在分叉之前帧完全相同：在到达者至少两个的节点上，动作的优势是选它者的平均回报减节点上全部到达者的平均（同一状态、不同动作、真实后果）。分叉之后，优势是段回报减组内平均，再减一个在组内去均值数据上拟合的岭回归（状态摘要：幕、楼层、HP、金币、卡组与遗物数），回归只有几十个权重，记不住单局。
- **不按标准差归一**。回报二值、组小，除以组内标准差会把 1 胜 3 负这类组放大。
- **Boss 入场切点**。分叉之后一段的几百条决策共用一个段回报，共享前缀只覆盖百分之几；死亡有一半在 Boss 战，而一次用药只是其中一条决策。在一幕的第一场 Boss 战的第一个决策再切一级：前一波到此停下、写入场存档，Boss 波从存档重进这场战斗（敌人 HP 与开局手牌重抽）打到下一幕开头或终局。回报沿同一条链回传：第三幕 Boss 波是 ±1，前两幕的 Boss 波取下一幕组的均值；到达 Boss 的段取它那组 Boss 波的均值。一组 Boss 段从同一入场状态开始、同一帧分叉，共享前缀树在这里覆盖整场战斗的开头。

### 更新：裁剪目标

- **温度化的策略**。每个决策是按其阶段的温度 T 从 π_T ∝ π^(1/T) 抽出的；argmax 与温度无关，greedy 评估不受影响，所以被优化的就是 π_T。比值 r = π_θ,T(a)/π_old,T(a) 是同策略的，不需要温度修正。
- **损失**。−min(r·A, clip(r, 1±ε)·A) 加 κ 倍对这次运行起点策略的 KL(π_θ,T ‖ π_ref,T)（合法动作上精确计算）。优势为零的决策不被学：全赢或全输的组不会把策略往它已偏好的动作拉。
- **步长按信号定**。一轮里优势的可用信号远小于噪声：按 BC 的学习率走一遍，带符号的目标在噪声上随机游走，策略变平、KL 增大、评估变差。所以迭代用自己的一组小学习率（独立于检查点训练设置的学习率文件），κ 取较大值，让一轮用完全部样本的同时只走一小步，信号靠多轮累积。
- **批的构成**。整轮是一个数据集，一条决策每进一次批的权重相同，与波无关；各波在批里的份额决定它进批的次数，所以一波的份额就是它在梯度里的占比。默认份额按各波的决策数定，一遍（ΣN / B 次更新）把每一波各看一次，各波的贡献与决策数成正比；第一幕的优势幅度随后两幕变强而变大，它的梯度份额随之自动增长，不用手调。份额可改，等份额会把第一幕每条决策放大约十倍、同时让第三幕一半样本进不了批。

### 护栏与门槛

- 每几次迭代 500 局评估，与进入迭代的检查点配对比较；通关率显著变低就停。
- 每次更新的策略熵（温度 1）低于阈值时，在这次迭代完成后停（`--min-entropy`）；KL、裁剪比例、比值均值逐更新记录。
- 门槛：若干次迭代后 500 局配对评估显著高于进入迭代的检查点。

### 采样温度

战斗 0.3、局外 0.5，按引擎的遭遇事件划界，战斗中的选牌按战斗温度。局外温度更高时探索吃掉大量通关，组里能比较的通关段变少。温度是策略定义的一部分，记在对局与检查点里；评估取最可能动作。

### 不采用的做法

- **整局 PPO，或局内外联合的整局 PPO**：问题出在整局回报的优势估计，一局三百多个宏动作共用一个 ±1，换优化器不解决。
- **按种子分组的整局组基线**：同一种子整局的差异主要来自对局中途的随机性，组内平均减掉的方差有限；按幕续打让组共享更长的起点。
- **胜率模型（critic）给每步定价**：标签是一局一个胜负，一局几十个决策共用它，模型在“记住训练对局”和“读不出 HP 等状态”之间两难，过不了留出门槛；它给出的优势会被加权 BC 放大。组续局的平均直接是状态价值的蒙特卡洛估计。
- **优势加权回归（AWR）**：exp(A/β) 加权的 BC。A = 0 的样本权重为 1，全赢或全输的组照样被拟合；对 T < 1 抽出的样本做加权 BC 的最小点是 π_T，每一遍都在削尖策略，与优势无关；β 调小后权重集中在少数样本上。温度修正 min(c, π/π_T) 只在期望上抵消，截掉的那部分仍让目标比 π 尖，有限样本的最大似然漂移照样单向流失熵。两次试跑都塌缩（熵 0.60 → 0.11，通关 17% → 2%），代码已删。
- **监督锚（通关轨迹窗口）**：把策略自己最近的通关链当监督样本防漂移。一局赢了不代表其中每个选择都好，它只是加权 BC 的另一份数据；裁剪目标的漂移由 KL 约束，不需要它。随 AWR 一起删。
- **战斗从入场存档重打、按战后估值比较**：需要给战后状态定价，没有价值模型就没有奖励；幕组的续局把战斗的影响连同其后果一起计入。
- **起步之后继续用示范或求解器标签训练**：示范的局外水平是人类的，求解器的战斗标签带隐藏信息，二者都不等于学生能力；在学生状态上补求解器标签的续训没有带来提升。
- **逐项消融结构、扫宽度**：换不来路线上的信息。Muon 学习率在 200M 本身上用两条短探针确认。

### 已知风险

- 信用分配粗：分叉之后一段的全部决策（第三幕约两百个）共用一个段回报，共享前缀只覆盖很少的决策；单个关键决策分到的信用很小。Boss 入场切点把 Boss 战单独成组，其余决策点仍只有段回报。
- 步长过大时裁剪目标在噪声上扩散（熵升、KL 涨），一轮之内就把策略推离起点；防线是小学习率、KL、熵阈值和评估。
- KL 参考默认固定为运行起点：策略真变好之后会被往回拉；可以每 k 次迭代把参考换成当时的策略，代价是约束变成只管最近 k 次的漂移。

## 评估

- 固定种子、五角色各 100 个开发集种子共 500 局、greedy，与训练使用相同的对局循环（`python -m main evaluate`）。开发集与训练种子（含示范的 seed 分组）、最终测试集互不重叠；最终测试集不用于反复选型。
- 两个检查点按（角色，seed）配对比较（`python -m main compare`）：通关、过第一幕、过第二幕各做精确符号检验，只数两边不一致的配对。通关率与各幕通过率带 Wilson 95% 区间；同时报前 300 局（每角色前 60 个种子）。未完成的对局算没通关，报告标为不可直接比较。
- 报告首要看五角色平均通关率，另报最弱角色、各幕通过率、平均到达楼层和止步楼层（诊断量，验收只看通关率）。
- 多引擎合批的前向在近似并列的决策上会随批次组成翻转，同一检查点重跑的通关数相差几局不是信号；500 局的 95% 区间约 ±2.7 个点，结论只看配对检验。
- 训练数据按 seed 分组固定留出约 2%，永不训练，只用于比较 NLL（`python -m main heldout-nll`）；判定是 seed 的函数，同一 seed 在任何导入、子集和分片布局下都落在同一侧。

## 示范数据

唯一的生成方法是**摘要锚点**：只用对局摘要（`.run`）逐节点重建状态，每个决策在原生引擎里从对应的节点边界单独开始，互不延续。战斗由 CombatSolver 求解并在另一进程逐步重放；局外标签是摘要记录的人类选择，或按游戏可接受的顺序重建的选择（标 `reconstructed_order`）。摘要没写下、但由这一局 seed 决定的东西让游戏自己再生成一遍，必须等于记录；对不上的隔离。历史没有记录的状态按规则补全并标明来源，这些是合成状态，不是历史快照。样本保留角色、难度、来源完整性与 seed 分组；求解器的战斗标为 `teacher_visibility=privileged`。细则见 [demos](implementation/demos.md)。

## 优化器与精度

Transformer 的 Attention/FFN 矩阵用 Muon；查找表（符号、字段名、各层关系偏置表）、Norm 与头用 AdamW，各自一组学习率。查找表按标准正态初始化、经字段求和后的归一化只看相对变化，与线性层共用小学习率时实际停在随机初始化上，所以独立成组：从初始化出发时第一轮内从 `1e-2` 几何衰减到 `1e-3`，之后恒定；续训只用衰减后的值，因为在已训练网络上 `1e-2` 会破坏已学内容。默认 BF16 autocast；实体编码器、决策头、对数概率与加权损失用 FP32（小批上的 FP32 矩阵核末位差异进入 BF16 会被放大）。细则与数值见 [network](implementation/network.md)。
