- **时间**：每过一幕给 1／2／3 的那次 RL 日期记录未留存（只见于用户 2026-10-15 的补充）；过幕积分 `act-progress-v2` 于 2026-10-06 接入；`ppo-v1`、`ppo-v2` 在 2026-10-10 运行；同日用户改为只给通关 ±1；整局 PPO 代码 2026-10-11 删除（`66614f0`），过幕积分等术语同日删除（`27e7f38`）。
- **来源**：`.scratch/joint-training/issues/06-seed-variance.md`（2026-10-15 Comments）、`.scratch/joint-training/issues/07-act-groups.md`；`.scratch/a0-training-baseline/implementation-report.md`「首批」；`8c50964` 的提交信息与 `cf9a06e`、`8c50964` 时的 `ARCHITECTURE.md`「PPO」节；`e525af6` 删除的 PPO 节。`ppo-v1`／`ppo-v2` 的原始工单 `.scratch/a0-training-baseline/issues/12-ppo-baseline-run.md` 已删除，数字取自会话记忆。
- **状态**：没带来提升；奖励被只给通关 ±1 取代，PPO 代码已删除。

## 动机

整局只在终局给奖励时，BC 策略按概率采样几乎不通关，开头的轮次回报全是 −1、优势约为 0。过幕积分想给出更早、更密的信号，先把采样策略练稳。

## 做法

### 每过一幕 1／2／3 的 RL

每过一幕给一次奖励，三幕依次 1、2、3。其余设置记录未留存。

这次与 git 历史里的奖励都对不上：2026-09-22 起仓库里有 PPO 价值预热（`7ed5879`），`bb0b1ee^` 时的奖励是 `milestones-v1`（0.005／0.02／0.1／0.2／1.0，见 [01](01-1b-first-design.md)）。它可能是项目早期或仓库之外的一次尝试。

### `act-progress-v2` 与 `ppo-v1`／`ppo-v2`

- 奖励：“通过第一幕 +1，通过第二幕 +2，通过第三幕／整局通关 +5……通关基础总分为 8”；普通、精英、事件战斗不另给奖励，正常死亡保留已得分数。
- 无折扣蒙特卡洛回报，`A_global = G_t − V_old(s_t)`；PPO 裁剪、价值 MSE、熵项；旧策略重放一致性检查；`ppo_muon_lr=2e-4`。
- 多进程采样：64 个引擎每轮 80 局，耗时 204 s → 31 s。
- 对照的 BC 是 `trained-v8-potions` 第 17 轮（开发集前 300 种子 greedy 通关 37 局）。

## 结果

### 每过一幕 1／2／3 的 RL（据记忆记录）

“模型只学会把概率集中到 greedy 动作上，平均推进层数没有增加；第一幕还学会多睡觉、把药水留给 Boss，只为拿到过第一幕的奖励。”

### `ppo-v1`／`ppo-v2`（据记忆记录）

- `ppo-v1`：靠过幕积分先把采样策略练稳，“第 8 轮后才有约 4% 的通关”（采样）。
- `ppo-v2`：开发集前 300 种子 greedy 通关，BC 37 → 第 20／40／60／70 轮 32／42／25／29；过第一幕 63% → 74–79%；在示范上的 NLL 0.87 → 1.53。“没有示范项时策略在示范上的 NLL 一路上升……各阶段都升。”
- 四段 PPO 的检查点、各轮数据与评估输出在 2026-10-10 21:25 按用户要求全部删除。

## 原因分析

- **奖励的期望不是通关率**。策略优化的是“过第一幕”：多休息、把药留给第一幕 Boss，卖掉的是后面几幕的实力。过第一幕从 63% 涨到 74–79%，通关却在 25–42 之间来回。
- **截断的奖励没有接上后续价值**。过幕时状态的好坏（卡组、HP、药水）不进回报，策略没有理由为后面保留实力。
- **一个回报管三百多个宏动作**。噪声梯度下出牌“越推越糙”，示范上的 NLL 各阶段一起涨。
- **只削尖，不改进**。在自己的结果上做监督，主要效果是把概率集中到已偏好的动作，greedy 评估看不到收益。

## 结论与后续

- 2026-10-10 用户看到 `ppo-v2` 的结果后，把奖励改为只在终局给通关 +1、不通关 −1（`outcome-v1`），见 [12](12-outcome-ppo.md)；`outcome-v1` 至今是基础奖励，见 [env 奖励](../implementation/env.md#奖励)。
- 整局 PPO 与价值头在 2026-10-11 删除（`66614f0`）；过幕积分、局部优势等术语在 `27e7f38` 从 CONTEXT 删除。
- 这条教训直接定了幕组的回报：前一幕的回报是下一波从它的存档续打的组的平均回报，而不是“到达下一幕”，见 [architecture 幕组的回报与优势](../architecture.md#幕组的回报与优势)。按战斗给掉血、用药的塑形奖励也因此不做。

## 教训

- 截断到一幕的奖励必须接上幕末状态的价值（从这里继续、最终通关的概率），不能只奖励过幕。
- 中间指标（过第一幕）涨而通关不涨，说明奖励与目标错位，不是训练不够。
- 只用自己的结果做监督的方法主要在削尖分布。
