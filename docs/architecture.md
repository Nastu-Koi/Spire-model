# 系统架构

为《杀戮尖塔 2》训练一个只看玩家公开信息、覆盖整局的策略，目标是**五角色 A0 平均整局通关率**。主模型用公开状态的实体编码器、带关系偏置的 Full Attention 全局层和无状态决策头，做包括战斗在内的全部决策；普通宝箱、指定单选事件和水晶球格子由固定控制器处理。术语见 [CONTEXT](../CONTEXT.md)，用法见 [README](../README.md)，各模块的实现见 [implementation/](implementation/)。本文写当前设计及其理由；试过而放弃的做法、实测数字与路线的演变在 [trials](trials/route.md)，任务进度在本地 `.scratch/`。

## 设计原则

- **先小后大**。约 20M 的小配置（`configs/rtxpro6000.json`）验证训练路线，路线的每一步在 20M 上过门槛后才转向约 200M（`configs/rtxpro6000-200m.json`）。200M 不重走路线，而是以 20M 的最终策略为蒸馏源，从随机初始化蒸馏起步（[ADR 0002](adr/0002-distill-200m-from-20m.md)，未实现）。目标规模取 200M 而不是 1B：示范的量撑不起十亿参数的行为克隆，1B 的采样前向也让迭代成本不可接受。
- **只用行动前公开信息**。保留完整合法动作集合、无序牌堆的重复数量与排列不变性，以及公开且有意义的顺序。
- **每个决策都给完整公开状态**，局内局外都带地图；吞吐问题从编码侧解决，不裁剪输入。
- **训练信号来自同一起点的多条续局**。整局只有一个 ±1，三百多个宏动作共用它，单个选择的价值被整局噪声淹没。对局按幕切成几段，每幕从幕开头的存档续打几条，组内平均回报作基线，后一幕的组均值作前一幕的回报；不训练价值模型。局内局外的决策在同一个批里一起更新，因为局外选择的价值取决于战斗能否用好它，战斗的价值也只通过战后的局外状态体现。（ADR 0001 改为局外与战斗分开取信号，实现中。）
- **示范只用于起步**。行为克隆从摘要重建的人类示范和求解器战斗起步；起步之后策略只从自己的对局学。（ADR 0001 让战斗在强化学习之前再做一段求解器示范的 BC，实现中。200M 不做示范 BC，从 20M 蒸馏起步，见 ADR 0002。）
- **效果只认配对评估**。结论来自固定种子、五角色均衡的 500 局 greedy 配对比较；训练采样的胜率不是证据。

```

  env/       引擎协议、控制分工、奖励、入场存档、种子与划分（含采样轮的种子派生）、公开历史、引擎进程、进程计时
  encoding/  公开观察 → 实体与程序、规则文本、冻结词表、批打包
  data/      分片与索引、样本与权重、留出规则
  network/   网络、优化器、检查点、选择与可微重放
  play/      对局循环、多进程采样（含跨进程的决策打包格式与采样时的编码表）、幕组采样（可另记每场战斗的入场存档与战况）、战斗组采样（从入场存档续打、截在战斗结束）、回溯分叉（战斗组的段重放到危急帧、拿不准的决策与某回合开头，分成喝药、强制动作与对照几条续打）、战斗评估集（固定入场存档的逐场对局、打法与求解器结果的读取）、战斗示范的挑选（每轮交给求解器的战斗）、药价拟合的取点与配对续打（战后选图点，原样与去掉一瓶药各续打到下一幕开头）、评估报告、合成引擎
  demos/     示范导入（摘要锚点导出）、逐轮的战斗示范（求解器子进程与导入）
  learn/     数据供给、加权 NLL 训练器；不属于哪一种训练的段与回报、组内岭回归、采样数据的流、裁剪目标；GRPO 的幕组优势、幕组批、幕组更新；混合批（局外幕组、战斗组、战斗示范同批，目标按来源分派）；战斗代价与药价（战况记账；药价模型：入场状态的线性价、按来源对局分折的岭回归、逐幕倒推、与旧价平滑）；战斗组优势（战况现算回报、组均值基线与分叉树；回溯分叉同此，另按分叉点类型记喝药臂对对照、前两名动作之间的诊断）；战斗评估报表（平均代价、与求解器的差距、行为差异表）

spire_codex_data/   公开对局下载、来源审计、摘要账本、锚点生成、入场存档的战斗（示范生成）

public_history/     无头与 Steam 共用的公开历史状态机（C#）
steam_takeover/     Steam Mod：实机接管的控制桥接（C#）
sts2-cli/           无头引擎
```

依赖只朝一个方向：`env ← encoding ← data, network ← play, demos ← learn ← iterate ← commands ← cli`；`demos` 与 `play` 同级，供 `commands` 与 `steam` 使用；顶层模块（`iterate`、`value`、`steam`、`commands`）可以引用其下任何一层；`cli` 是入口，只引用 `commands`，没有模块引用它。`data` 与 `network` 互不依赖。`main` 内部除顶层模块外不引用 `spire_codex_data` 与 `combat_solver_cli`，后两者反过来引用 `main`。`main/tests/test_layers.py` 检查这一点。

## 数据流

```
Spire Codex 摘要 ─ spire_codex_data（锚点 + 求解器）─ demos 导入 ─┐
                                                                 ├─ BC 起步（两段）─ 检查点
                                                                 │
检查点 ─ play 幕组采样（第一幕从开局，之后每波从上一波的幕开头存档续打；战斗 greedy）─ 各波的段
各波的段 ─ 回报沿链回传 ─ 组内优势（共享前缀的分叉树 + 组内基线）─ learn 一遍更新 ─ 新检查点
各波的战况与入场存档（greedy 战斗）─ 挑选（3:4:4、自然频率、开局选择先挑）─ 求解器（entry_battles，子进程）─ 导入 ─ demos/imported（BC 阶段每轮一份）
战斗示范目录（最近几轮的 demos/imported）─ 只取战斗、按份额抽 ─ 与各波同批（NLL，不算 KL）─ learn 一遍更新
各波的战况与入场存档（greedy 战斗）─ 挑选（3:4:4，死亡与代价高的优先、一半均匀）─ 战斗组（每场续打 K 条，截在战斗结束）─ fight-groups 波 ─ 按种类取主干、重放到分叉点（回溯组：危急帧每种药一条强制喝加两条对照，拿不准的决策前两名各强制两条，某回合开头四条照常选）─ fight-hindsight 波 ─ 两波的战况按药价现算回报 ─ 组内优势（共享前缀的分叉树 + 组均值）─ 与幕组同批更新
检查点 ─ 来源对局的战后选图点 ─ 原样与去掉一瓶药的配对续打（greedy，到下一幕开头）─ 配对差 ─ 药价模型（岭回归、逐幕倒推）─ 与旧价平滑 ─ prices.json ─ 战斗组的挑选与回报（fit-prices 手动；iterate --potion-prices）
新检查点 ─ 每几次迭代 500 局 greedy 评估 ─ 配对比较（compare，手动）
检查点 ─ 战斗评估集（固定入场存档）greedy 逐场打到战斗结束 ─ 战况 ─ 平均代价；同一批存档上求解器的结果 ─ 差距与行为差异表（fight-eval，手动）
```

训练命令（`bootstrap`、`iterate`）把检查点写进 `checkpoints/` 下这次运行自己的目录（默认是 `checkpoints/` 加输出目录在 `runs/` 下的相对路径），输出目录只有运行记录：运行身份、状态、历史与每步记录、种子、幕组摘要、评估报告。检查点大、要长期保留和被别的运行引用；运行记录小、随运行清理。

## 输入与公开信息

`decision_frame` 由 `contract`、`routing`、`public`、`legal.candidates` 组成。模型只用行动前公开信息；seed、内部随机数、隐藏牌序、候选编号和对象地址不作特征，引用只用来建立实体关系、把动作映射回游戏操作。

- 公开实体和完整动作库各成为 token（地图除外，见“地图压缩”）。没有公开顺序的牌堆保留完整多重集合，同名牌不合并，打包下标不加位置编码；效果执行顺序、公开槽位等有意义的顺序另行表达。
- 字段编码：每个字段的身份是符号 embedding 加字段名 embedding；数值由以字段身份为输入的 MLP 编码后与身份相加（数值必须与字段绑定，否则 `hp=12, block=40` 与 `hp=40, block=12` 相同）。数值特征为 `value/100`、带符号 `log1p`、`known`、`applicable`、`is_numeric` 和 8 组周期 4 到 2048 的正余弦。字段求和后按字段数平方根归一化，未知值不等于零。
- 全局标记（第 0 个 token）带阶段与多选进度；已选实体带 `selected`，顺序有意义时带 `selected_order`。
- 正在结算的牌在[出牌区](../CONTEXT.md)（zone `play`）里公开，出牌引出的选牌因此能读到触发牌的规则文本；出牌区为空时不发布。
- **公开历史**由系统维护并显式输入，不加循环状态：战斗内保留上一回合敌人意图、抽牌堆里公开已知的位置、药水掉落概率；局外保留问号房间概率和药水掉落概率。无头与 Steam 编译同一份状态机（`public_history/`）；中途接管或缺前缀时为 unknown，不从隐藏存档补值。训练自己写的续局存档带着写存档那一局观察到的公开历史，从它续打的段接着用，所以幕组的后两幕与战斗组也有完整的公开历史。
- 契约：`public-state-v7`、`public-history-v1`、`public-encoding-v3`。公开历史不兼容的检查点不能用于当前输入。

## 局部程序与规则文本

一个 token 可以带一段局部程序（节点与类型化关系），经局部注意力层编码后取根节点加池化汇入该 token。来源有三种：引擎的效果程序；规则文本（引擎标为 `OPAQUE_RULE` 的卡牌、遗物、药水、能力、充能球、事件选项，程序取自游戏自己的描述文本）；地图程序。解析不依赖权重，按内容缓存；批内相同程序只编码一次，按节点数分组。采样时实体与程序的编码还按内容留在采集进程的编码表里，一轮之内同一份内容只编码一次（见 [play](implementation/play.md#采样进程分工)）。

规则文本让内容之间共享语义：公开对局里大部分内容只出现几次，只靠内容 ID 学不出含义，而描述文本按定义是完整的公开语义。模板按实体公开值渲染，值不公开的变量保留为 unknown；程序是根节点加按顺序的词节点，顺序只在相邻、前后关系里。选项文本里的变量分数值（`amount`）和内容名（`names`，指向目录里已有的内容符号）。规则文本属于输入，摘要写入检查点，不一致即拒绝。规则编码器与主策略都从随机权重开始，不用预训练语言模型。

## 地图压缩

地图节点里只保留当前节点、**地图前沿**和仍被引用的节点。每个前沿节点带一段地图程序：从它出发可达的全部节点（房间类型、楼层、列、相对深度，Boss 节点带遭遇），节点对之间的关系为自身、直接连接、间接可达、自由通行的单步、不可达。整张地图会在每个阶段占去大部分 token，而决策需要的正是“选这个节点之后会遇到什么”。自由通行成立时后继加上下一层全部节点，只靠自由通行的一步单独成一种关系。

## 全局骨干

全局层全部是双向 Full Attention，SwiGLU FFN。实体之间的类型化关系是加性注意力偏置：每种关系对每个头一个可学习标量，每层一张表（各层可以沿不同关系聚合）。没有偏置时，两个字段相同、只有一个带易伤的敌人，“打 A”和“打 B”在输入端相同；有了偏置，动作沿 `target` 找到目标，目标沿反向 `owner` 找到能力。

结构只有一种（`architecture_version` 3）：query/key 归一化、残差输出投影按 1/√(2L) 缩小、字段间注意力、决策头的 query/key 归一化、线性层无偏置、RMSNorm。20M 与 200M 是同一结构的两个尺寸（宽 256 与 768、24 层）；其它结构版本的检查点按版本拒绝载入。

## 冻结的名称表

字段符号、字段名、关系角色三张表随检查点冻结。登记的名称各占一行；冻结后才出现的名称哈希到空行，报告为 `unregistered_names`；未登记的符号共用 `<unknown>` 并带字段名前缀报告。冻结时登记的内容来自引擎静态目录和表示层的完整枚举，不依赖碰巧见过哪些帧；新增一种引擎导出的名称时登记是必须的一步。

## 决策头

全局标记的最终状态 `h₀` 作查询：动作分数 = `query(h₀) · key(h_action) / √d`，非法动作屏蔽。每个决策独立编码、不保留状态；多选逐步进行，进度来自输入。策略网络没有价值头。

## 环境步骤与控制分工

| 决策 | 由谁做 |
| --- | --- |
| 普通宝箱（含问号房间里的） | 控制器：开箱 → 领取遗物 → 离开 |
| 只有一个可用事件选项、其余只能丢药 | 控制器推进该选项 |
| 水晶球格子与工具 | 公开几何规划器（不读隐藏布局与随机数） |
| 奖励界面上的金币、遗物与有空位的药水（只在 `--claim-rewards` 时） | 领奖控制器（`claim-free-rewards-v1`，示范按这个假设重建） |
| 战后与事件领奖（默认）、水晶球支付、遗物触发的选牌、商店、战斗 | 主策略 |

控制器步骤记为环境操作证据，不产生策略损失、不计入样本数与权重；无头、Steam、示范导入、训练共用 `main/env/control.py` 的同一套判断（`public-control-v1`）。

候选只包含有结果的动作：免费查看（已生成的卡牌奖励、商店货架、地图）由适配层展开进观测；无结果的返回不是候选；打开即产生结果的（开箱、重掷）保留为候选，内容揭示后才进观测。非战斗的可取消选择（锻造、商店删牌、移除奖励）**打开即承诺**，不发布 `CANCEL`，避免“打开 → 取消”的无结果循环。

## 训练路线

[ADR 0001](adr/0001-separate-combat-training.md) 调整了这条路线：局外仍用幕组 GRPO，但幕组里的战斗固定为 greedy，战斗决策不进幕组的更新（见[采样温度](#采样温度)）；战斗单独训练，先用求解器示范做 BC（从幕组里 greedy 打过的战斗入场存档求，求解器补上开局选择、按新药价定价），再用从入场存档续打、截在战斗结束的战斗组做强化学习，回报按求解器的记账（[战斗代价](../CONTEXT.md)；`iterate --fight-groups`，见[战斗组采样](#战斗组采样)）。一遍更新的批里同时放局外幕组、战斗组与战斗示范（[混合批](#混合批)）。BC 阶段的逐轮示范（`iterate --round-demos N`，默认 0）：每轮在优势之后从这一轮 greedy 打过的战斗里按 3:4:4、自然频率挑 N 场（开局是选择的先挑）交给求解器，赢下的战斗导入后，更新学最近 `--demo-buffer` 轮的示范（[play 战斗示范的挑选](implementation/play.md#战斗示范的挑选)、[demos 逐轮的战斗示范](implementation/demos.md#逐轮的战斗示范)）。

1. **BC 起步**。示范来自摘要锚点（见 [demos](implementation/demos.md)）：局外是人类在重建状态上的选择，战斗是求解器在重建入场状态上打出的动作。分两段：第一段拟合 A0–A10 全部示范；第二段严格续训、只拟合 A10，战斗换成按更大预算另求的 A10 战斗。第二段每轮留检查点，选 A0 评估最好的一轮作起点。
2. **幕组迭代**。每次迭代：
   1. 当前策略按采样温度打一轮幕组：每个种子从开局打 n 条到第二幕开头（写幕开头存档），每份第二幕存档续打 m 条到第三幕开头，每份第三幕存档续打 m 条到终局；可以让各组的难度在一个窗口里分配（见下）；
   2. 每一波按组算优势（见下）；
   3. 一遍更新：每个逻辑批按份额从各波取样本，裁剪目标；
   4. 每几次迭代 500 局评估。
3. **200M**（[ADR 0002](adr/0002-distill-200m-from-20m.md)，未实现）。20M 路线结束时评估最好的检查点作[蒸馏源](../CONTEXT.md)，200M 从随机初始化做[策略蒸馏](../CONTEXT.md)，不做示范 BC：
   1. **离线蒸馏**：蒸馏源按训练时的温度打整局，战斗也留帧；200M 在这些帧上拟合蒸馏源在温度 1 下的分布（每个决策的 KL(π_源 ‖ π_θ)，权重同示范 BC），逐轮采、学一遍即删。留出的蒸馏 KL 不再下降后，在开发集上与蒸馏源配对比较。
   2. **在策略蒸馏**，按需：配对显著低于蒸馏源时，改由 200M 采样、蒸馏源现算分布，目标不变。
   3. **之后**用自己的采样走第 2 步。门槛是配对显著高于蒸馏源，过不了就以 20M 为准。

   不迁移 20M 权重：宽度扩展不保函数，所以迁移的是分布而不是参数。不再从示范起步，是因为 20M 的能力主要来自 BC 之后的强化学习，而强化学习在 200M 上每一步都慢几倍。

### 幕组的回报与优势

- **回报**。最后一波是终局 ±1（`--win-hp-bonus β` 时通关另加 β × 剩余 HP / 最大生命，见下一条）；之前每一波的段若到达边界幕，回报是下一波从它的存档续打的组的平均回报，一波波往前传。前一幕的回报因此是“从这里继续，当前策略最终通关的比例”的蒙特卡洛估计，而不是“到达下一幕”：后者是截断奖励，会奖励多休息、留药水这类只顾眼前的做法。
- **剩血奖励**。通关率上来以后，第三幕的组越来越多是全赢的同结果组，整组剔掉（见下一条），一轮里剔掉的局外决策比留下的还多。通关时另加 β × 剩余 HP / 最大生命（β 取 0.1）：赢得越轻松的打法排在前面，全赢的组因此分得开。只加在整局最后一场：第一、二幕 Boss 之后幕初回到约九成血，剩血几乎被抹平，而第三幕的结果已经沿链传回前两幕。β 要小，免得拿胜率换血量：从 0 血赢到满血赢最多抵 5 个百分点的胜率。幕组里战斗是 greedy，所以它推动的是局外决策（路线、休息还是升级、选牌）往"打完剩血多"走；战斗组本来就按掉血计代价。
- **分幕的理由**。三幕各自开局，组内各段共享更长的起点、视野更短；后一幕的组均值把这一幕之后的随机性平均掉一部分，所以前一幕的回报方差小于整局 ±1。
- **优势**。同一组的段在分叉之前帧完全相同：在到达者至少两个的节点上，动作的优势是选它者的平均回报减节点上没在这里探索的到达者的平均（同一状态、不同动作、真实后果；全都探索时取全部的平均）。探索的动作策略几乎从不选，与策略自己的选择等权计入节点均值的话，它更差时会把均值拉低，照常走的分枝就白拿一份正优势，头号选择每轮被额外强化（工单 33：有探索兄弟的节点上 +0.01 至 +0.03）。分叉之后，优势是段回报减组内平均，再减一个在组内去均值数据上拟合的岭回归（状态摘要：幕、楼层、角色、HP 比、最大 HP、金币、卡组／遗物／药水数、是否在战斗中），回归只有十几个权重，记不住单局。下一波那组没有一条完成的段时，这条段没有回报、不参与更新。
- **全组同结果的组**。组内各段回报全相等时，树上节点的优势全是 0，分叉后的优势只剩 −βᵀΔφ（与结局无关、组内 R² 很小的噪声），只有 KL 项还在起作用。回报沿链传回，第一、二幕基本只有“全在本幕死”或“后续全赢”才全组同结果；第三幕续局胜率高，这类组多是全赢。Muon／AdamW 的步长与梯度大小基本无关，这些决策稀释的是一步的方向。所以这类组像没有回报的段一样不进更新：岭回归只在保留的组上拟合（剔掉的组目标全 0，会把 β 往 0 拉），份额与一遍的步数按剔除后的决策数算，组数、组间方差占比、全组同结果的组数照旧按全部的组记。
- **不按标准差归一**。回报二值、组小，除以组内标准差会把 1 胜 3 负这类组放大。
- **难度窗口**。`--ascensions LO HI` 让每个（角色，种子）的组在 [LO, HI] 里分到一个难度（各角色的种子轮流取窗口里的各级，每级组数至多差一），续局从存档进、沿用存档的难度，所以一组的段、一条链上的组都同难度。基线按组算、回报沿同一条链回传，难度高低只改各组的平均回报，不进优势；岭回归在组内去均值的数据上拟合，也不受组间难度差影响。正式评估仍按检查点的难度（A0）。窗口第一版在两次运行之间按评估手动上移。动机是难度越高，局面越紧，用药这类动作的后果越大、越容易在组内比较出来；代价是分到 A0 的组变少，高难度下第一幕死得多、后几幕的段变少。

### 更新：裁剪目标

- **温度化的策略**。每个决策是按其阶段的温度 T 从 π_T ∝ π^(1/T) 抽出的；argmax 与温度无关，greedy 评估不受影响，所以被优化的就是 π_T。比值 r = π_θ,T(a)/π_old,T(a) 是同策略的，不需要温度修正。
- **损失**。−min(r·A, clip(r, 1±ε)·A) 加 κ 倍对参考策略的 KL(π_θ,T ‖ π_ref,T)（合法动作上精确计算；参考每隔评估间隔（`--evaluate-every`）换成当时的策略，第一段是运行起点；参考就是采这一轮的策略时，KL 对采样时记下的分布算，不再跑参考前向）。优势为零的决策不被学：全赢或全输的组不会把策略往它已偏好的动作拉。
- **步长按信号定**。一轮里优势的可用信号远小于噪声，步长大了带符号的目标就在噪声上随机游走（策略变平、KL 增大）。所以迭代用自己的一组小学习率（独立于检查点训练设置的学习率文件），κ 取较大值，让一轮用完全部样本的同时只走一小步，信号靠多轮累积。一步的样本数是另一个旋钮（`--batch`，累加几个加载批，学习率不变）：Muon 的更新经正交化、幅度与梯度大小无关，一步方向里信号的占比随样本数涨；但一遍的步数随之减少，噪声主导时一遍累积的信噪比与批大小无关，只是整体位移缩到 1/√k，约等于降步长；只有一步里的信号不可忽略时大批才真正占优。
- **批的构成**。整轮是一个数据集；波与波之间，一条决策每进一次批的基准权重相同，各波在批里的份额决定它进批的次数，所以一波的份额就是它在梯度里的占比。默认份额按各波的决策数定，一遍（ΣN / B 次更新）把每一波各看一次，各波的贡献与决策数成正比；第一幕的优势幅度随后两幕变强而变大，它的梯度份额随之自动增长，不用手调。份额可改（`--wave-shares`），偏离决策数比例会放大某一波每条决策的权重、并让别的波有样本进不了批。剔掉全组同结果的组后，决策数是剔除后的：同结果的组多的波（第三幕）份额随之变小。波内按（角色，阶段）组等分权重、单条决策不超过平均份额的 10 倍，与示范 BC 的阶段平衡相同。

### 混合批

[ADR 0001](adr/0001-separate-combat-training.md) 让局外与战斗共享一个网络、在同一个批里更新（实现见 [learn 混合批](implementation/learn.md#混合批)）。

- **三类来源，各成一路**：局外幕组（各波一路）、战斗组（一路）、战斗示范（一路）。前两类是采样样本，走裁剪目标加对参考策略的 KL；示范走每个宏动作在温度 1 下的 NLL，与 BC 相同，不算 KL。KL 管的是采样样本把策略带离参考的漂移：BC 阶段局外样本带 KL，示范的梯度就不会把局外行为带偏；示范的标签不是策略的样本，对它算 KL 没有意义。
- **同一尺度，没有系数**。任何一类的一个宏动作每进一次批，平均权重都是 1/B；一类的份额就是它在梯度里的占比。份额默认按决策数（示范按示范池的宏动作数），也可以按类给定；BC 阶段定为局外与示范 1:1（`--source-shares act-groups=1 combat-demos=1`）。一遍把局外各波各看一次，其余各路按份额取。
- **示范只取战斗**。示范目录里只取含战斗的样本组，连同战斗内的选牌；留出种子组也训，示范的留出另有一份（战斗评估集上求解器的轨迹）。一遍要的示范多于目录里有的就整场重复，少就整场抽一部分；抽取按种子根与迭代号可复现。示范是最近 `--demo-buffer` 轮的导入，每轮换一组。
- **只有局外一类时，更新与没有混合批时逐步相同**（同种子同批的损失与参数更新逐位一致，有测试钉住）。
- 记录按类分开：损失、样本数、正确率，采样类的 KL、裁剪比例与比值，示范的 NLL；顶层的 KL 与裁剪比例只算采样样本。

### 护栏与门槛

- 每几次迭代 500 局评估（`--evaluate-every`）；与进入迭代的检查点的配对比较用 `compare` 手动做，通关率显著变低时由人决定停下。驱动不按评估结果自动停。
- 一次迭代的更新在其决策上的平均策略熵（温度 1）低于阈值时，驱动在这次迭代完成后停下（`--min-entropy`）；KL、裁剪比例、比值均值逐更新记录。
- 门槛：若干次迭代后 500 局配对评估显著高于进入迭代的检查点。

### 采样温度

战斗 0.3、局外 0.5，按引擎的遭遇事件划界，战斗中的选牌按战斗温度。局外温度不取更高：探索会吃掉通关，组里能比较的通关段随之变少。温度是策略定义的一部分，记在对局与检查点里；评估取最可能动作。

**greedy 战斗**（幕组固定如此；[ADR 0001](adr/0001-separate-combat-training.md) 的第一步）：幕组采样时战斗内的决策也取最可能动作，只有局外决策按温度抽。战斗组与回溯分叉照常按战斗温度抽，评估全部取最可能动作。

- **为什么**。战斗相当于固定为评估时的打法，引擎在动作给定时确定，组内各段的差别只来自局外决策及其后果；局外决策的优势就是"按评估时的战斗打法，这个选择的好坏"。
- **战斗决策完全不进幕组的更新**：不进批、不算 KL、不计入份额与决策数，不只是优势为 0。它们不是从温度化策略里抽出来的，比值与 KL 都无从谈起；战斗另行训练（ADR 0001）。实现上这些战斗不留帧，对局只记它们的计数与对数概率。
- **残余**：多引擎合批的 bf16 前向会让近似并列的战斗决策偶尔翻转，所以战斗并非严格固定。

### 探索步

组内比较只能比较采样里出现过的动作。采样时被换掉的决策（[局外探索](#局外探索)、先验提议、回溯分叉在危急帧强制喝的药）记为探索步 `explored`，记下的 `old_log_prob` 是策略自己对这个动作的对数概率，更新把它当成同策略样本按优势推。不按行为策略的概率做重要性修正：探索步上行为策略选这个动作的概率远大于 π_T(a)，修正后的比值远小于 1 − ε，信号会全部被裁掉；这个偏差是有意的，被推的只是优势不为零的探索动作。评估不探索。

探索步在更新里**按得分推**，不受比值窗口约束。被探索的动作概率很小，温度 T 下它的对数概率变化是 logit 变化的 1/T 倍；一遍里每条样本只被看一次，看到它时的比值是此前各步留下的漂移，1 ± ε 的窗口实际是在按漂移决定用不用这条样本。单侧裁剪会让与运动方向相反的样本以整个比值拉、方向相同的被裁掉，系统性压低它；双侧裁剪又会把漂出窗口的样本正负一起静音，漂移随之只沿共享方向累积、与证据无关。所以探索步取比值在 r = 1 处的切线 A·(1 + log r)：那里与 r·A 同值同梯度，之后梯度恒为 A·∇log π_θ,T(a)，漂移既不静音也不放大它；只有对数比值超过一个很宽的保险界才停（`Sample.explored`、`Clipped`）。约束仍来自小学习率与 KL。回溯分叉的强制候选（分叉步 `forked`）选的是排第一或第二的，不稀有，照旧双侧裁剪（`Sample.forked`）。

### 局外探索

幕组里局外决策的组内比较，同样只能比较采样里出现过的选择。策略在局外越训越确定，局外温度下一个只占几个百分点的候选几乎抽不到：同一帧上没有别的段选过它，分叉树在这里没有可比的东西，确定但选错的决策也就改不过来。采样时按阶段的探索率（`--explore-outside`，一个率用于全部局外阶段，或按阶段给）让幕组里有选择的局外决策不取策略最可能的候选：一半取第二可能的，其余在剩下的候选里均匀取一个，从不取丢药。探索步记为 `explored`、记策略自己对这个动作的对数概率、按得分推（见[探索步](#探索步)）；回报照旧打到整局结束。同一帧上一段探索、另一段照常时，分叉树在这里给出同一状态、不同选择的优势。战斗组与回溯分叉不做局外探索，评估不探索，默认率为 0。各波优势头另记局外探索步的数量、优势均值与其中落在分叉树上的个数。

不用提高局外温度代替：温度把探索均匀撒在全部决策上、主要落在本来就拿不准的地方，而局外探索只在被抽中的决策上换一个候选，每段每幕的探索次数由率直接控制。

探索的候选也可以由先验提议（`--explore-prior`、`--prior`）：先验是与策略同词表的另一个网络，现用的是当前检查点的副本只在 A10 人类胜局的局外决策上做过 BC，留出集上的局外 NLL 与 BC v12 相同。采样时按阶段的率抽中的局外决策先问先验最可能的候选；它不是策略最可能的、也不是丢药时，取它，记为探索步，标 `explored_by: "prior"`；两者一致时这个决策照常（再按 `--explore-outside` 的率抽签）。先验只提议、不接管：没有往先验拉的损失，提议值不值只由回报决定。先验的网络在收集进程里，采样进程把这类决策走单独的一路（自己的编码表与已发送记录）去问它，不用每批都过两个网络。不接管的理由：先验的局外配当前的战斗，A9 只有 58/500（当前策略自己 163），人类的局外以人类的战斗为前提。

只学树上的探索步（`--explored-on-tree`）：不由分叉树定价的局外探索步不给优势（0），只有同组另一段在同一帧选了别的、优势是同状态下两种选择之差的那些才推。树外的探索步优势是整段回报对基线，主要是这一段其余部分的运气，而探索步的得分项不受比值窗口约束、对稀有动作的梯度约是普通决策的 30 倍，均值略负的噪声累积下来会把所有备选一起压低（第十五段：固定决策集上的局外熵 0.229 → 0.185，被探索备选的概率降到约 1/42）。各波优势头的 `explored_outside` 按提议来源（`prior`、`rule`）分记全部与树上的数量和优势均值，供同轮对照两种提议。

探索步优势去均值（`--explored-centered`）：参与学习的局外探索步，优势按波、按阶段减去它们自己的均值。探索的备选平均不如策略的头号，这是策略已经知道的；照原样学，负优势的探索步更多，经共享参数泛化成“头号以外都差”，策略逐轮变尖（工单 33：第十六段固定决策集上的局外熵每轮下降；探索步优势全置 0 时一轮里反而从 0.230 升到 0.240）。去均值后探索步整体不推，留下的是哪个提议比其他提议好；代价是对备选有一点乐观偏差，以及先验的提议平均比规则的好时，对先验有一点净拉力。

### 战斗组采样

[ADR 0001](adr/0001-separate-combat-training.md) 的战斗强化学习从这里取数据（`iterate --fight-groups N`；实现见 [play 战斗组](implementation/play.md#战斗组)）。

- **挑哪些战斗**。从这一轮幕组里 greedy 打过的战斗中挑 N 场：事件战斗没有入场存档，不挑；普通、精英、Boss 默认按 3:4:4 分配（`--fight-group-shares` 可改），每类一半按优先级（死亡在前，再按[战斗代价](../CONTEXT.md)从高到低），一半在其余战斗里均匀抽，免得只练难打的战斗。某类不够时如实记下，不从别类补：补了就改了配比。随机数按种子根与轮次定，同一轮重挑相同。幕组是扇出的（每局第一幕 n 段，之后每份存档再续 m 段），直接从记下的战斗里挑会让第三幕的战斗多出几倍（4／4／4 时第一幕只占约 13%）；`--fight-group-natural` 先按自然频率（每场取所在谱系在这一波的段数的倒数，每局每幕计一次，同战斗示范的挑法）把每类稀释到配额的 2 倍，再在留下的里按优先级与均匀抽。
- **外部入场池**（`--fight-pool`、`--fight-pool-share`）。战斗组的一部分可以从轮外的入场存档里抽，比如按人类 A10 胜局的入场状态重建的战斗：策略自己的入场状态是它自己的局外塑造的，局外换风格时战斗没见过那种牌组。池里的战斗按种类分配同上、类内均匀抽（策略没打过，没有代价可排），其余仍从这一轮挑。
- **怎么打**。每场从入场存档续打 K 条（默认 8，可按种类另定，如 Boss 16 条：`--fight-group-kind-size`），组内平均回报是基线。战斗按检查点的战斗温度抽、留全部帧（与幕组的 greedy 战斗相反：这里比的就是战斗内的决策），不探索、不强制。
- **截在战斗结束**。段停在战后第一个决策（或下一场战斗的第一个决策：十阶第三幕两个 Boss 可以相连）或终局，不再续打到下一个切点：回报只看这一场的战况，战后的价值由药价与死亡惩罚接上（ADR 0001 的风险一条）。
- **优势**。回报是这场战斗的[战斗代价](../CONTEXT.md)取负再除以 100，由战况按传入的药价现算、不落盘，换药价不用重采。组内均值是基线；同组各段从同一份存档开始，在第一次选了不同动作之前帧都相同，这段共享前缀上用与幕组相同的分叉树给动作级优势，分叉之后是回报减组均值，不做状态回归。全组同结果的组与幕组同样整组剔除。优势文件与幕组的一波格式相同，头里按战斗种类记组内诊断：全同组、生死有分歧的组、同组里用药段与不用药段的死亡率与代价之差（实现见 [learn 战斗组的优势](implementation/learn.md#战斗组的优势)）。
- **药价**。默认是求解器那套固定价 7／9／11（整局最后一场 1／1／1）。`fit-prices` 拟合出[药价模型](../CONTEXT.md)后，`iterate --potion-prices` 改用它。价格只取决于[入场状态](../CONTEXT.md)、角色、难度与药水本身，战斗里的打法只通过掉血、用药与死亡影响代价，不会反过来改价。死在这场战斗里时不计药价：整局随之结束，腰带里的药一起作废，喝掉与留着同样不值钱。一次迭代的战斗组按采样时的价格挑选，也按同一价格算回报。拟合与平滑见 [learn 药价模型](implementation/learn.md#药价模型)。
- **成长奖励**。单场的代价看不到一场战斗给后面留下的东西：长了数值的卡（遗传算法、镰刀），斩杀拿到的最大生命、金币、卡牌奖励（血肉盛宴、贪婪之手、狩猎），以及计数带到下一场、停在快触发处的遗物。`--growth-bonus` 给了时，每个这样的事件从代价里减固定的 HP（第六段 0.5）；死在这场或整局最后一场不给。它和药价一起进价格摘要，挑选与回报按同一份算。
- **回溯分叉**（`iterate --fight-hindsight N`）。战斗组的组均值只比较整段打法：一组的段在第一次选了不同动作之后就各走各的，之后几十个决策共用一个段回报，关键回合（快死时喝不喝药、Boss 的爆发回合）分不到信用。所以每轮从战斗组的段里按普通、精英、Boss 3:4:4 均匀取 N 条主干（不论死活），按主干自己的动作从入场存档重放到选定的决策（续打在动作给定时确定，重放回到同一帧），在那里分成[回溯组](../CONTEXT.md)，抽到战斗结束；同一状态下各臂的后果之差就是这一步的优势。每条主干至多三个点，按[分叉点类型](../CONTEXT.md)选，只看帧上的信息、不看结局（按死亡挑段、按"最后一回合"选点会让点偏向输局）：
  - `danger`：第一个危急帧，每种能喝的药一条强制喝（探索步，按得分推）、两条照常由策略选：快死时喝不喝药在同一状态上比；
  - `uncertain`：第 2 回合起，策略合并等价候选（同一张牌的两份副本、同一目标）后前两名对数概率最接近的决策，前两名各强制两条（分叉步，双侧裁剪）：用的是段采样时记下的分布，不再跑前向；
  - `turn`：第 2 回合起随机一回合的第一个决策，四条照常由策略选，免得只看难点。
  回溯组按战斗组的算法定价、算优势（重放的前缀不学），更新时作为战斗组那一类的第二路，两路按决策数分这一类的份额。细则见 [play 回溯分叉](implementation/play.md#回溯分叉)、[learn 战斗组的优势](implementation/learn.md#战斗组的优势)。
- **更新**。战斗组一波写在轮目录下、与幕组各波并列，但不在幕组的波列表里，幕组的优势不读它；更新时作为[混合批](#混合批)的一路（裁剪目标加 KL）。

### 战斗快循环

[ADR 0005](adr/0005-fight-fast-loop.md)（试行中）：局外冻结，只训战斗。每轮仍采一个小幕组（每角色几个种子），它只提供两样东西：战斗组的入场存档（另一半来自人类 A10 训练池），与局外决策上对起点的 KL 样本。

- **局外冻结**（`--freeze-outside`）：幕组各波的优势全为 0，只剩 κ·KL(π_θ ‖ π_起点)；参考固定为起点（`--evaluate-every` 取得比运行的迭代数大），所以战斗的更新带偏局外时被拉回。
- **战斗不加 KL**（`--fight-kl 0`）：只靠裁剪约束一步的位移，学习率比幕组 GRPO 大（BC 的 0.3–1 倍），可走多遍（`--passes`）。
- **奖励简化**：战斗代价只算 HP、最大生命、固定药价与死亡，不加成长奖励、不用拟合药价；整局评估另做。
- **主指标**：人类 A10 战斗基准（同一入场状态逐场比掉血），整局 A9 只看局外有没有被带坏。

### 不采用的做法

整局 PPO、胜率模型（critic）定价、按种子分组的整局组基线、优势加权回归（AWR）与监督锚、战斗从入场存档重打按战后估值比较、起步之后继续用示范或求解器标签训练、采样与更新并行等做法都试过或论证过并放弃；每一项的做法、结果与原因见 [trials](trials/route.md)。其中"战斗从入场存档重打"与"起步之后继续用求解器标签训练"由 ADR 0001 以新的形式恢复：战斗按实测战况记账、不经估值模型，示范只训战斗、与局外的幕组 GRPO 同批，之后接战斗组强化学习。

求解器的任何变体都不作为"只看公开信息的打法上限"或策略的学习目标，包括在回合间[重新播种](../CONTEXT.md)、让它只按抽样出来的未来规划的做法：续打在动作给定时是确定的，求解器的每个决策都是靠搜索到的未来作出的，换一个未来只是换了它看见的未来，并不去掉它对未来的依赖（用户 2026-10-25 定）。求解器只用于给出战斗示范、作诊断，以及"局外策略 + 局内求解器"的整局评估（量局外决策在战斗打满时的上限）。

### 已知风险

- 信用分配粗：分叉之后一段的全部决策共用一个段回报，共享前缀只覆盖很少的决策；单个关键决策分到的信用很小。战斗组的回溯分叉只覆盖少数点，其余决策仍只有段回报。
- 步长过大时裁剪目标在噪声上扩散（熵升、KL 涨）；防线是小学习率、KL、熵阈值和评估。
- KL 参考每隔评估间隔换成当时的策略，约束只管最近几次迭代的漂移；固定为运行起点会在策略真变好之后把它往回拉（[trials 31](trials/31-fixed-kl-reference.md)）。

## 评估

- 固定种子、五角色各 100 个开发集种子共 500 局、greedy，与训练使用相同的对局循环（`python -m main evaluate`）。开发集与训练种子（含示范的 seed 分组）、最终测试集互不重叠；最终测试集不用于反复选型。
- 战斗另有[战斗评估集](../CONTEXT.md)：从策略自己的对局里取的 440 份入场存档，普通、精英、Boss 3:4:4，固定不变（`python -m main fight-eval`）。策略 greedy 逐场打到战斗结束，按战斗代价（固定药价）比较检查点的战斗打法，另报死亡率、用药数、死时持药未用的场数和危急帧上的用药概率；同一批存档上求解器打的结果给出逐场的代价差与行为差异表，作诊断。它是战斗 BC 转强化学习的判据之一（ADR 0001）。集的种子与开发集一样不进采样（`--exclude-seeds`）。同一检查点 FP32 重跑也有少数战斗因合批的近似并列翻转而打法不同。细则见 [play](implementation/play.md#战斗评估集)、[learn](implementation/learn.md#战斗评估报表)。
- 两个检查点按（角色，seed）配对比较（`python -m main compare`）：通关、过第一幕、过第二幕各做精确符号检验，只数两边不一致的配对。通关率与各幕通过率带 Wilson 95% 区间；同时报前 300 局（每角色前 60 个种子）。未完成的对局算没通关，报告标为不可直接比较。
- 报告首要看五角色平均通关率，另报最弱角色、各幕通过率、平均到达楼层和止步楼层（诊断量，验收只看通关率）。
- 多引擎合批的前向在 bf16 下会让近似并列的决策随批次组成翻转，整局随之分岔，同一检查点重跑的通关数并不相同；评估可以关掉 bf16（`--precision fp32`、`--eval-precision fp32`）减小这部分噪声。500 局的 95% 区间约 ±2.7 个点，结论只看配对检验。
- 训练数据按 seed 分组固定留出约 2%，永不训练，只用于比较 NLL（`python -m main heldout-nll`）；判定是 seed 的函数，同一 seed 在任何导入、子集和分片布局下都落在同一侧。

## 示范数据

主要的生成方法是**摘要锚点**：只用对局摘要（`.run`）逐节点重建状态，每个决策在原生引擎里从对应的节点边界单独开始，互不延续。战斗由 CombatSolver 求解并在另一进程逐步重放；局外标签是摘要记录的人类选择，或按游戏可接受的顺序重建的选择（标 `reconstructed_order`）。摘要没写下、但由这一局 seed 决定的东西让游戏自己再生成一遍，必须等于记录；对不上的隔离。历史没有记录的状态按规则补全并标明来源，这些是合成状态，不是历史快照。样本保留角色、难度、来源完整性与 seed 分组；求解器的战斗标为 `teacher_visibility=privileged`。另一来源只有战斗：求解器从幕组采样记下的入场存档重打策略打过的战斗（ADR 0001 的战斗示范），同样在另一进程逐步重放、只导出打赢的。细则见 [demos](implementation/demos.md)。

## 优化器与精度

Transformer 的 Attention/FFN 矩阵用 Muon；查找表（符号、字段名、各层关系偏置表）、Norm 与头用 AdamW，各自一组学习率。查找表按标准正态初始化、经字段求和后的归一化只看相对变化，与线性层共用小学习率时实际停在随机初始化上，所以独立成组：从初始化出发时第一轮内从 `1e-2` 几何衰减到 `1e-3`，之后恒定；续训只用衰减后的值，因为在已训练网络上 `1e-2` 会破坏已学内容。默认 BF16 autocast；实体编码器、决策头、对数概率与加权损失用 FP32（小批上的 FP32 矩阵核末位差异进入 BF16 会被放大）。细则与数值见 [network](implementation/network.md)。
