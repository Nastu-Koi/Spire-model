# 01–05 验证记录

本记录维护实现范围与验收证据；工单状态以各工单文件为准。01–05 的局部功能与评测验收已完成；不能据此宣称整局产出目标达成。

## 生产边界

`PublicPlanner` 使用 `CombatModel` 的同一公开状态转移能力。每次只提交一个原生合法动作，然后重新观察；预测不写回引擎。`EffectPrediction` 区分 `modeled`、`approximate`、`unknown`，未知效果没有虚构后继状态。所有根合法候选均获评分。

新增公开观察：玩家 `lost_hp_this_turn` 为本回合未格挡损血事实，治疗不撤销；非战斗为 null。药水 `stats` 提供公开动态参数。观察清洗保留这些字段，不提供引擎随机状态、隐藏牌序或游戏 seed。旧观察缺少损血事实时，Spite 按单次伤害作近似并截断。

## 效果覆盖清单

下表为 `cards` / `potions` 配置的覆盖边界；不是全游戏原生模拟。未支持的力量效果、遗物、附魔和附加状态会触发未知边界。当前仅放行 Burning Blood、Fishing Rod、Lost Coffer、Kaleidoscope：原生钩子分别在战后治疗、战后升级或获得遗物时发奖励；当前帧中的奖励已公开，不会在本回合出牌／用药中改写即时效果。Miniature Cannon、Slippery、Shrink、Rage 等仍会阻断，不能因其高频就忽略。

| 原有卡牌 | 当前转移与限制 |
| --- | --- |
| Strike | 单目标面板伤害，力量、虚弱、易伤、格挡 |
| Defend | 面板格挡，敏捷、脆弱 |

| Hemokinesis | 先自损再攻击；更新分支损血事实 |

新增 Second Wind 按剩余非攻击手牌逐张消耗并逐次计算格挡；正在打出的牌不计入，自身正常进入弃牌堆。Spite 仅在公开损血事实为 true 时采用 Repeat。Weak 与 Vulnerable 的乘法合并后取整，不逐修正取整。

药水覆盖 Fire Potion、Explosive Ampoule、Block Potion、Weak Potion、Strength Potion、Energy Potion。伤害与格挡药水不受力量、虚弱、易伤、敏捷或脆弱的普通卡牌修正。虚弱按可见意图每击计算；同时存在玩家易伤时标记取整不确定。补能只更新资源并作为叶节点，不宣称发现新合法组合。未支持药水保留合法候选，使用公开参数作明确近似。

## 可重复评测

冻结输入见 [开发／保留种子与五个配置](01-05-manifest.json)。本轮只运行 dev；四个开发种子、每配置重复两次。各相邻配置依次启用 Second Wind、Spite、通用卡牌修正、药水。游戏 seed 只交给运行器，独立采样配置交给教师；当前当回合搜索没有随机抽牌采样。

从仓库根执行：

```bash
PATH=/tmp/spire-model-dotnet9:$PATH DOTNET_CLI_HOME=/tmp/spire-model-dotnet-home python3 -m combat_solver_cli.public_evaluate --manifest .scratch/public-search-repair/evidence/01-05-manifest.json --split dev --output combat_solver_cli/artifacts/repair-01-05/development-final
```

输出目录必须尚不存在，以免覆盖已有证据。运行器保存原始公开决策、每动作预测与原生净变化、版本哈希和重复差异。初始化、失败、提前放弃、未完成尝试、独立验证与导出均计时。零成功时成功成本为 null。相邻公开边界的净变化可能包含自动效果，不能不加区分地解释为某张牌的单独效果。

受控原生夹具必须 `training_ready=false`，不会导出为训练轨迹。原生测试用 `STS2_NATIVE_EFFECT_TESTS=1 python3 -m unittest combat_solver_cli.tests.test_public_effects_native -v` 启用；需要上述 .NET 9 运行环境。正常战败属于完整运行，随机角色回归不证明教师胜率。
