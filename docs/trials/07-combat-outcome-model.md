## 动机

“用户此前训练的主要困扰是单次选择的价值变化被整局结果噪声淹没。保留全局 Monte Carlo 回报传递长远价值，另用本幕通过势提供较近反馈。”

## 做法

### 已实现：单场战斗结果模型

- 学习“入场状态（卡组、遗物、药水、入场 HP）× 遭遇 → 单场净损血和是否战败”，输出标量损血与战败 logit（数据 `combat-outcomes-v2`）。
- 网络复用策略的实体编码器与全局注意力层，配置 2 层、宽 128、FFN 344。
- 数据三个来源格式相同：摘要锚点的战斗（求解器打）、学生状态的战斗（从入场存档由求解器另打）、采样时策略自己打的战斗（对局循环写 `<对局>.combats.jsonl.gz`）。
- 对照基线：只用遭遇与入场 HP；卡组汇总特征的岭回归；汇总特征加卡牌／遗物词袋的岭回归。

### 规划中：Φ 与两路优势

- 战斗结果分布 → 聚合成本幕通过概率 Φ。
- 局部优势 `A_local = E[Φ(s′) | s, a] − Φ(s)`，策略优势 `A_actor = A_global + β·A_local`。
- 加一项对冻结 BC 参考策略的 KL。

## 结果

- README 写明：“结果分布、完整 Φ 和随机后态期望尚未实现，也未证明局部信号能改善通关率。”
- 单场回归的 R²、平均绝对误差：记录未留存。
- 盘上的导出 `anchors/combat-outcomes.jsonl.gz`（77 MB）删除代码时没有动。

## 原因分析

- **链太长**。“先预测每场战斗的结果分布、再聚合成本幕通过概率、再验证每一步的边际，这条链的每一环都要单独校准；一个直接回归通关概率的 critic 用同样的采样对局就能给出每步的时序差分优势。”（`4ffe8ca^:ARCHITECTURE.md`）
- **分工重复**。“战斗怎么打由求解器标签教，战斗的代价由 critic 跨过战斗的差分计入，不需要另一个模型。”
- **数据偏**。入场状态来自人类胜局，“弱卡组、低 HP 入场的情况少，战败只占少数”；同一状态只打一次，标签带一次战斗随机数的噪声；最后一场 Boss 之后 HP 不再有用，求解器不保它，掉血不代表必要代价。

## 结论与后续

- 2026-10-11 用户决定抛弃原路线：删除 `combat_outcome/` 包、`configs/combat-outcome.json`、对局里的 `<对局>.combats.jsonl.gz`、锚点与学生战斗导出里的 `combat-outcomes.jsonl.gz`；CONTEXT 删去本幕通过势、局部／全局优势、过幕积分等术语。学生战斗的胜负与入场遗物改由入场存档行提供。
- 取代它的“胜率模型直接回归通关概率”后来也失败了，见 [19](19-win-prob-critic.md)；之后的路线不训练价值模型，前一幕的价值由下一波组的平均回报给，见 [architecture 幕组的回报与优势](../architecture.md#幕组的回报与优势)。
- 用户明确要求不再提议战斗结果模型、Φ 塑形或对局内的战斗标签。

## 教训

- 由多个模型串成的估值链，每一环都要单独校准；能用一次蒙特卡洛估计直接给出的量，不要拆成几段预测再拼。
- 只来自人类胜局的入场状态覆盖不到学生会走进的弱状态，在它上面学到的“战斗代价”对学生不成立。
