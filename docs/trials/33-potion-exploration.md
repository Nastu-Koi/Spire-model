一局的期望用药数：T=1 下 3.9 瓶，T=0.5 下 0.84，T=0.3 下 0.51（greedy 实际 0.41）。π_T ∝ π^(1/T)，T = 0.3 时 1% 对 60% 的比值从 1/60 变成约 1/10⁵。没被抽到的动作得不到梯度，KL 又把策略拴在同样不用药的参考上：不探索 → 没信号 → 概率不升 → 更不探索。起点也低：求解器示范在普通、精英、Boss 战里用药 1%、5%、9%，人类玩家两成、五成、三分之二。结论是行为策略从不产生用药样本，要在采样时主动造出用药的段。

## 做法

- 方案 F1（用户 2026-10-18 确认）：`--explore-potions p`，采样时战斗里带 USE_POTION 候选且候选数 ≥ 2 的决策，以概率 p 改为只在 USE_POTION 候选里按 π_T 的相对概率抽；记下的 `old_log_prob` 仍取整个合法分布下的 π_T(a)（“假装同策略”：若诚实做重要性修正，比值约 π_T(a)/p ≈ 10⁻³，信号会被全部裁掉）；步记 `explored: true`，优势头统计探索步的数量、优势均值与正负个数。
- p = 0.02：v16 每局约 300 个有药可用的战斗决策、约 15 场战斗，每场约 20 个；一场带药的战斗至少探索一次的概率 1 − 0.98²⁰ ≈ 33%，相当于原计划的“每场 0.2–0.3”。
- 运行：`runs/grpo-20261017/launch/v17-v22-explore.sh`，从 v16（`train/v12-v16/policy/iteration-0004`，也是 KL 参考）起 6 次迭代，种子根 `grpo-explore`，其余与 v12–v16 相同，评估间隔 2。输出 `train/v17-v22-explore`。

## 原因分析

先排除了“幕组 GRPO 对稀有动作的一般性侵蚀”：不探索时 BC v12 → v16 的用药概率一直在升（0.75% → 1.31%，排第一的帧 33 → 41），是策略自己偶尔抽到的、有把握的用药（低 HP 时的格挡药水）拿到正优势被强化。F1 的 6 轮把它打回 BC 的水平，是探索本身把概率拉下去了。工单按把握从高到低列了三条机制：

1. **探索率定错量级，把腰带用光**（有数据支持）。每段第三幕约 300 个有药可用的决策，p = 0.02 下实测每段探索用药 2.7 次（act3 约 17k／6,300 段；act2 2.6，act1 1.9），而一段只有约 3 瓶药：几乎每瓶药都在随机时机被探索掉。“打到精英、Boss 时还带着药”的状态在采样里几乎消失，此前上升的来源——自然用药的正样本——随之消失。
2. **稀有动作上裁剪目标的不对称**（假设，未用保留分片坐实）。探索步的 log π_T(a) 约 −6，一遍内变化快（对自身 logit 的系数 (1 − π)/T ≈ 3.3，KL 按 π 加权几乎不约束）。min(r·A, clip(r)·A) 下，概率先被推高时 A > 0 的样本被裁掉、A < 0 的以 r·A 往下拉；先被压低时 A < 0 的被裁、A > 0 的只以 r·A（r < 1）往上推。上升被放大的反作用打回、下降只被削弱的回复力顶住，一遍遍系统性下滑。
3. **随机时机的用药接近中性**（有数据支持）。探索步优势均值 +0.015～+0.020（约 0.75% 通关率）、正负约 60:40，可能还混有“药多的局本来就强”；2/3 的可用药帧 HP ≥ 60%、近半在普通战，普通战里的弱负样本把精英、低 HP 的正样本连带拉低——降幅最大的恰是 HP<30%（3.3% → 1.5%）与精英战（2.7% → 1.6%）。

## 结论与后续

- v22 不采用；当时 v16 仍是最新可用，v20 作为评估最高的检查点保留。
- 同时否决的方案（工单 27 方案表）：
  - F2 按动词的温度：改变“被优化的就是 π_T”的定义，评估的 argmax 与采样不再一致。
  - F4 奖励塑形（死时手里每瓶药 −v、丢弃 −v）：与“回报只用终局 ±1”相悖，可能学成低血乱用或早早用光。
  - F5 BC 起点加权：20M 不再重做 BC，留给 200M 的 BC 起步。
  - F6 战斗温度 0.3 → 0.5：用药概率均值 0.17% → 0.28%、一局期望 0.51 → 0.84 瓶，不够，且通关段变少。
- 取代它的 F1′（2026-10-18 13:28，`409eda2`）：探索率按战斗种类给（`--explore-potions 0.008 0.02`：普通战约每幕 0.5 次，精英与 Boss 每幕 1–2 次）；探索步双侧裁剪（`where(inside, r·A, detach(r·A))`，比值在 1 ± ε 外两侧都不推）。从 v20 起跑 v23–v28，只跑完两轮就暂停：第 1 轮各波探索步／段 act1 1.56、act2 1.80、act3 1.97，按种类实测普通约 0.37–0.57 次／幕、精英加 Boss 1.13–1.21 次／幕；v24 迭代内 178 胜、整局 bf16 180、FP32 175／176，对 v20 180:174（p = 0.69）、对 v16 180:162（p = 0.18）；同帧 T=1 用药概率 0.90% → 1.10%，但 T=0.3 0.127% → 0.112%、greedy 用药帧 32 → 26，整局用药 0.33 瓶／局（9.3%）仍在降。工单把“自然用药的优势为负”列为下一步要验证的假设。v25 起的正式训练从 v24 起，结论未定。
- 未做：低 HP 门限；Boss 入场处的用药分叉（F3）；用保留一轮分片复算 log π_T 来坐实机制 2。
- 代码：F1 的接口没有删除，演化为按种类的率（给一个数时三种战斗同率，仍能表达 F1）；探索步与分叉步共用双侧裁剪。设计见 [architecture 用药探索](../architecture.md#用药探索)，实现见 [play 温度与战斗边界](../implementation/play.md#温度与战斗边界) 与 [learn 幕组的裁剪目标](../implementation/learn.md#幕组的裁剪目标)。

## 教训

- 探索率要按资源预算（腰带约 3 瓶）定，不能按“每场至少探索一次”定；探索把资源用光，会抹掉策略原有的正样本。
- “假装同策略”的稀有动作需要双侧裁剪，否则单侧裁剪会系统性压低它。
- 归因之前先看“不做这项改动时的趋势”：同帧探针在五个检查点上排出时间线，才分清是探索的作用还是一般性侵蚀。
- 不要给跑过的输出目录改名：`saves.jsonl` 里的存档路径含目录名（[35](35-operational-incidents.md)）。
