# KL 参考固定为运行起点

- **时间**：2026-10-16 定为固定起点；2026-10-17 加 `--reference-every k`（默认仍固定）；2026-10-18 用户定改默认，2026-10-19 完成
- **来源**：`.scratch/joint-training/issues/act-groups-grpo.md`（08 的取舍一节、Comments“四项候选改动的核查”）、`update-settings.md`（18、33）；`.scratch/joint-training/spec.md`（开放问题）
- **状态**：被修正的旧默认。改为“参考每隔评估间隔换成当时的策略”是按机理的修正，没有做过固定与刷新的配对评估。

## 动机

裁剪目标里的 KL 项抵消自采样的有限样本漂移。工单 08 选了固定参考（迭代的起点检查点，当时是 BC v12）：防的是累积漂移；代价是策略真变好之后 KL 会把它往回拉，当时 κ = 0.01 很小，先这样。

## 做法

- 08：π_ref 固定为 `--checkpoint`，每次更新载入、同批前向一次、不求导。
- 18：`Settings.reference_every`（`--reference-every k`），第 N 次迭代的参考在 N < k 时是起点检查点，否则是 `iteration-{k·⌊N/k⌋ − 1}`，即当前这段 k 次迭代开始时的策略，每段的第一次更新对参考是同策略的、KL 从 0 起；这些归档在清理时保留。默认 0，即不刷新，行为不变。

## 结果

- 08 的核查（`iterate-v5` 前两轮，κ = 0.1）：两轮末尾 KL 0.011、0.017，参考还没开始起作用。
- GRPO v7–v11（`train/v7-v16` 运行）的 5 次迭代每宏动作 KL 0.007 → 0.025，每次约 +0.004；v17–v22（`train/v17-v22-explore`）0.007 → 0.027。
- κ = 0.1 乘 KL 0.027，到一次运行后期 KL 项的量级已与策略项（损失约 0.01）相当（工单 33 的判断）。
- 18 做完后默认仍是 0，没有任何运行用过它。实际上每次运行都从上一次的检查点重开，参考靠人工每 5–6 次迭代换一次。

## 原因分析

- 小步 GRPO 的 KL 对固定参考近似线性增长（[32](32-v12-v16-plateau.md)），运行越长，KL 项越大，越倾向于把策略拉回起点；这与“策略真变好”无关，只取决于走了多远。
- 靠人工重开运行换参考，要换输出目录、种子根和状态，不能断点续跑。

## 结论与后续

- 33（2026-10-19 完成）：`--reference-every` 不给时取 `--evaluate-every`，参考就是上一次评估过的检查点；`0` 仍表示整次运行固定为起点。v25 起的正式训练参考每 2 次迭代刷新（评估间隔 2），结论未定。
- 注意：旧运行目录续跑时没给 `--reference-every` 也会按评估间隔刷新；要保持旧行为得显式加 `--reference-every 0`。例如 v23–v28 的启动脚本 `--evaluate-every 2`，续跑第 3 次迭代（编号 2）起参考会换成 `iteration-0001`（v24）。
- 开放问题：没有“固定 vs 刷新”的配对评估。
- 现在的做法见 [architecture 更新：裁剪目标](../architecture.md#更新裁剪目标)、[architecture 已知风险](../architecture.md#已知风险) 与 [learn 幕组的裁剪目标](../implementation/learn.md#幕组的裁剪目标)、[learn 迭代驱动](../implementation/learn.md#迭代驱动)。

## 教训

- 默认值决定实际行为：可选的开关做完而默认不变，就等于没有用上。
- 改默认时要检查旧运行目录续跑的语义，并写明怎样保持旧行为。
- 按机理改的设计要在状态里写明“未做对照”，不要当成实测结论引用。
