# encoding：观察、规则文本、词表与批打包

`main/encoding/` 把决策帧变成网络读的张量，不需要模型权重。设计见 [architecture](../architecture.md#输入与公开信息)。

| 模块 | 内容 |
| --- | --- |
| `representation.py` | 公开字段白名单（`clean_frame`、`clean_public`）、观察（实体、字段、引用、程序、地图前沿）、冻结词表 `Vocabulary` |
| `rules.py` | 规则文本：本地化模板的渲染与切词 |
| `batch.py` | 观察 → 批（字段张量、引用、程序分组与去重、关系边、动作位置） |

## 公开字段

`clean_frame` 保留重放与路由元数据，只把白名单里的公开字段交给模型（`clean_public`）；候选的语义走同一条清洗路径。描述里显示的变量随描述公开：清洗 `stats` 时保留规则文本引用的变量（`rules.variables`）。抽牌、弃牌、消耗堆的公开顺序只通过关系表达，不保留原生数组下标。

## 规则文本

- 来源是 `sts2-cli/localization_eng` 的描述模板：按内容 ID 的类别查表，事件选项按文本键查，远古之民的遗物选项取对应遗物的文本，卡牌接上附魔与负面修改的附加文本。
- 模板按实体公开值渲染：`{Damage:diff()}` 成为带数值的变量节点；升级、复数、条件、卡牌类型等分支按公开值选定；值不公开的变量为 unknown；其余文本切成小写词和字面数字。
- 动态遗物事件选项的 `*.title` 仅在本地化目录里唯一对应遗物时映射为该遗物；Mad Science 按公开 `rider_effect` 选附加效果分支。
- 事件与营火的 `displayed_variable` 按 `owner_ref` 绑定到选项的 `stats` 后再渲染；变量名预先登记到词表，known/applicable 掩码随绑定保留。
- 选项变量：数值带 `amount`，内容名带 `names`（内容 ID），成为指向该内容符号的变量节点；对不上唯一内容的名字不导出。
- 无头引擎不显示按钮，发布事件帧时照按钮的做法填入变量；游戏的本地化查表在无头里只返回键名，引用了哪些变量取自随引擎加载的英文模板。Steam 端在界面显示后取状态，用同一规则导出。
- 全部词和变量名在冻结时登记；文本表的摘要写入检查点，加载时不一致即拒绝。

## 冻结词表

三张表（字段符号、字段名、关系角色）随检查点冻结，保存与载入严格保持顺序。冻结时登记引擎静态目录的全部内容 ID、事件与营火选项、奖励与商店条目类型、卡牌关键词与动作动词；表示层再补每个公开字段的数值与布尔符号、规则文本的全部词与变量、`stats` 变量、附魔与负面修改、引用／程序／地图／引擎关系的全部角色，以及引擎会导出但目录没列的名称（选牌奖励的替代选项、水晶球物品与工具）。

`public-encoding-v2` 增补 Mad Science 附加效果枚举，`v3` 增补选牌奖励替代选项并改正水晶球物品名。仅加载权重开始新训练时，新符号追加到空行，已有符号 ID、表与权重保留。

## 批打包

解析结果按内容缓存：同一实体的字段行按内容共享，规则文本按内容与公开值缓存。一个批内解析结果与实体绑定都相同的程序只编码一次，并按节点数分组。训练按 2 的幂分桶；采样只分两组（不超过 4 个节点的与其余的），因为采样的前向受解释器限制，每少一组就少一轮循环。两种分组只差数值噪声。

## 已知的坑

- 同一字段的两个未登记取值在输入端无法区分；引擎新增一种导出的名称时必须登记，否则静默共用 `<unknown>`（只在报告里出现）。
- 解析缓存在一局之内才有用，却会在每个采样进程里涨到上限；采样进程每打完一局清缓存。
