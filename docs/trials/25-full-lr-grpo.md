# 按 BC 学习率走的 GRPO 与几项被否决的小改

- **时间**：2026-10-16
- **来源**：`.scratch/joint-training/issues/act-groups-grpo.md`（08 的阶段 03 结果；Comments“四项候选改动的核查”，核查脚本在草稿目录 `an/uniform.py`）；`.scratch/joint-training/issues/update-settings.md`（10；32 的用户决定）
- **状态**：被否决。按 BC 学习率的 GRPO 一轮内把策略推离起点并显著变差；之后核查的三项小改都不做。取代它的小步 GRPO（BC 十分之一的学习率、κ = 0.1）是现行做法。

**版本号**：本文的 v13、v14、v15 是失败试跑 `iterate-v3` 检查点里的内部 `policy_version`，不是 GRPO vN。GRPO v0、v2 的内部版本也是 13、15，但它们是另一次运行（信号检验与 `iterate-v5`）的检查点。

## 动机

幕组上的 AWR 两次试跑都在削尖（[24](24-awr.md)）：加权 BC 让 A = 0 的样本权重为 1，全赢、全输的组照样被拟合，采样里 70–90% 的决策就是 argmax。需要一个没有信号就不动的更新：比值裁剪加对起点的 KL，A = 0 的样本没有策略梯度。

用户 2026-10-16 确认：KL 参考 v12、κ = 0.01、ε = 0.2，不除组内标准差，`iterate --objective grpo` 与 AWR 并存。

## 做法

- 被优化的策略取温度化的 π_θ,T：argmax 与温度无关，比值 r = π_θ,T(a) / π_old,T(a) 是同策略的，不需要温度修正。
- 损失 −min(r·A, clip(r, 1 − ε, 1 + ε)·A) + κ·KL，KL 是宏动作内各决策在合法动作上对参考的精确 KL 之和；参考固定为起点 v12。
- 不除组内标准差（Dr. GRPO）：回报二值、m = 4／8 时除标准差会放大 1 胜 3 负的组。
- 优势沿用幕组的分叉树加组内岭回归（[23](23-natural-fork-tree.md)）。
- 试跑：草稿目录 `groups-v3.sh`，`iterate --advantage act-groups --objective grpo --clip 0.2 --kl 0.01`，v12 起，输出 `runs/groups-20261015/iterate-v3`，种子根 `groups-v3`；每角色 10 种子，n = 4、m = 4／8，`--weight-cap 3 --min-entropy 0.45`，32 引擎，3 次迭代，第 3 次后 500 局评估。学习率沿用 BC（Muon 1e-3），每轮一遍约 800 次更新。

## 结果

3 次迭代跑完，未触发熵阈值，产物为内部 v15。

- 第一批同策略核对通过：比值 1.0004、KL 1.3e-6（GPU、bf16 采样与训练重放一致）。
- 熵（温度 1，每约 86 次更新的均值）：0.69 → 0.73 → 0.79 → 0.78 → 0.80 → 0.83 → 0.92（round-0 末，789 次）→ 0.86 → 0.82（round-1，315 次）→ 0.86 → 0.82（round-2，195 次）。方向与 AWR 相反：变平而不是变尖。
- KL（温度化，每宏动作）：前 86 次 0.08，round-0 均值 0.36、末尾 0.60，之后停在约 0.6。裁剪比例 0.11–0.23，比值均值 0.97–1.01；梯度裁剪比例从 0.29 降到 0。
- 采样（各轮的采样策略）：

  | 轮 | 采样策略（内部） | 到达第二幕 | 到达第三幕 | 第三幕段通关 | 段数 |
  | --- | --- | --- | --- | --- | --- |
  | round-0 | v12 | 0.49 | 0.426 | 0.50 | 1,928 |
  | round-1 | v13 | 0.295 | 0.208 | 0.25 | 828 |
  | round-2 | v14 | 0.24 | 0.109 | 0.21 | 560 |

  主要损伤在 round-0 的一遍更新里就发生了。
- 优势量级（round-2 各波 |A| 均值）：act1 0.021、act2 0.093、act3 0.475；零优势比例 2–4%（岭回归项让几乎所有样本非零）。
- 评估 500 局（内部 v15）：通关 32（6.4%），过第一幕 37.4%、第二幕 12.8%，平均楼层 21.3。与 v12 配对：通关 87 → 32（仅 v12 胜 73、仅 v15 胜 18，p = 5e-9），过第一幕 284 → 187（p = 5e-12），过第二幕 135 → 64（p = 2e-9）。

### 几项小改的核查

阶段 03 之后列了四个候选（`--updates 50`、只训第三幕或按 |A| 定份额、全赢全输组的优势置 0、重设 KL 参考），用 `iterate-v5`（即产出 GRPO v1–v6 的那次运行）round-1 的优势文件核查：

- **`--updates 50`**（每轮只走 50 步）：信号检验（见下）表明，把学习率乘 0.1 就能在用完全部样本的同时把一轮的 KL 压在约 0.01，于是改用学习率缩放，不用 `--updates 50`。
- **只训第三幕、按 |A| 定份额**：按当时对代码的理解，各波按决策数占梯度权重 8%／19%／73%，再乘各波 |A| 均值（0.19／0.30／0.56）占 |A| 质量 3%／12%／85%；act1 在批里占三分之一位置，对梯度只贡献约 3%，改份额对方向影响很小，不做。
- **全赢、全输组的优势置 0**：每波 24–31% 的决策在这类组里，但只占 |A| 质量的 4–5.5%（均方根 0.05–0.12，混合组的回报项 0.34–0.86）；岭回归组内 R² 只有 0.02–0.03。置 0 后方差约降 1%，不值得单独改。
- **重设 KL 参考**：两轮末尾 KL 0.011、0.017（κ = 0.1），参考还没开始起作用，不改；后来的处理见 [31](31-fixed-kl-reference.md)。

## 原因分析

- AWR 在噪声上削尖（熵降），带符号的裁剪目标在噪声上扩散（熵升、KL 涨），两者都在一轮之内把策略推离 v12 并变差。
- 共同点是一轮的步长远大于优势里的可用信号：学习率沿用 BC，每轮一遍约 800 次更新，第一幕的 |A| 只有 0.02 却仍占三分之一批。κ = 0.01 时 KL 要涨到约 0.6 才与优势项平衡。
- 当时没有证据表明这些优势的方向能改善 greedy；扩散本身说明梯度方向大半是噪声。
- 小改核查里“act1 只贡献约 3%”的前提有误：[26](26-equal-wave-shares.md) 后来发现当时代码实际是各波等份额，三波对梯度的贡献各约三分之一。这条结论在新的按决策数份额下才成立；“不做”的决定没有因此重新评估。

## 结论与后续

- 用户 2026-10-16 决定先做信号检验再接小步迭代：
  - 信号检验（`runs/groups-20261015/signal-v4`）：v12 起，每角色 50 种子一轮，`--clip 0.2 --kl 0.1 --lr-scale 0.1`。更新 4,145 次，熵 0.69 → 0.65–0.69，KL 0.005 → 0.012（均值 0.0098），比值均值 1.000，裁剪比例 2% → 6%。产物即 GRPO v0（内部 13）：95 胜（19.0%），对 v12 p = 0.48（仅 v12 胜 45、仅 v0 胜 53），幕组路线第一次没有变差。
  - 小步迭代（`runs/groups-20261015/iterate-v5`，每角色 25 种子，学习率 ×0.1、κ = 0.1，6 次迭代）：GRPO v2 106、v4 113、v6 121 胜；v6 对 v12 p = 0.002（40:74）。6 轮末的熵 0.69–0.72，KL 依次 0.011、0.016、0.020、0.023、0.024、0.026。
- `--lr-scale` 后由学习率文件取代（工单 10）：`configs/learning-rates-grpo.json` 正好是 BC 学习率的十分之一，`iterate --learning-rates` 读它。2026-10-18 用户在工单 32 再次确认：BC 的学习率步长太大，已证明学不到东西，不回去。
- 试跑目录 `runs/groups-20261015/iterate-v3` 于 2026-10-16 删除，数字只留在工单 08。`--objective` 参数随 AWR 一起删除（[24](24-awr.md)），裁剪目标是唯一的更新方式；`--updates` 仍可给一个步数，默认 `round`。
- 现在的做法：步长按信号定、学习率文件与 κ 的取法见 [architecture 更新：裁剪目标](../architecture.md#更新裁剪目标)，实现见 [learn 幕组的裁剪目标](../implementation/learn.md#幕组的裁剪目标)。

## 教训

- 判断“有没有信号”要先用很小的总步长做一次信号检验，而不是直接按监督学习的步长迭代。
- 学习率 ×0.1 加 κ = 0.1 能在用完一轮全部样本时把一轮 KL 压在约 0.01；减少更新步数做不到“用完样本”。
- 熵与采样到达率在一轮内就能暴露问题，比等评估更早。
- 按份额推算梯度占比之前，先用测试核对份额在代码里的实际含义。
