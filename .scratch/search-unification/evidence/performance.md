# 合并版本性能测试 — 2026-09-26

结论：合并完成，当前版本在冻结的三种子测试中 **903.765 秒、0/3 条独立验收成功**，未达到平均 300 秒一条成功轨迹的既有门槛。零成功时单位成功成本为 null，不能写成 0 秒，也不能推断所有种子都无法通关。

## 冻结条件

Ironclad A0，游戏 0.111.0，CombatSolver 0.44.0，RitsuLib 0.6.2。本机 M4 Pro。单 lane MCTS、rollout 256、开启风险 rollout／局部修复和回合计划复用，常规战斗预算 1000ms、Boss 5000ms，每 seed 300 秒软时间限制。全部三个原保留种子按顺序运行，没有调参、提前删除案例或加入其他本任务原生负载。沙箱不允许 ps，未核实系统其他负载；这不是最大线程吞吐实验。

[运行前计划](performance-plan.md)／[冻结清单](performance-manifest.json)／[完整报告与源码、DLL 哈希](performance-report.json)。源码及依赖哈希运行中无漂移。启动、失败、停止及所有实际超时均计入墙钟；无胜利候选，因此本轮没有发生成功轨迹的独立验收开销。

## 已定位的限制

第三局重复出现 unsupported_event_view:COLORFUL_PHILOSOPHERS。原生日志先记录 NullReferenceException，涉及 ColorfulPhilosophers.GenerateInitialOptions_Patch1；适配器随后在事件没有可绑定选项时返回错误（sts2-cli/src/Sts2Headless/RunSimulator.Phases.cs:158）。这证明该配置下的事件执行失败，尚不能仅凭堆栈确定是游戏、Mod 补丁还是 headless 初始化的根因。

[异常堆栈](performance-native-error.txt)／[原始错误前缀和日志的位置及哈希](performance-error-artifacts.json)。完整运行树与日志保留在 combat_solver_cli/artifacts/unification/performance-holdout/。本次不改变游戏或放宽验收来绕过错误。

## 耗时分析

保留集完成后，独立使用开发种子 BD1D31C2468C7C1F 做 60 秒单 lane profile，参数使用同一默认 MCTS＋回合计划复用。[原始 profile](performance-profile.json)。此测量不计入保留集的 903.765 秒；整个本次原生性能工作另包含这 60.016 秒诊断测量。

- 总墙钟 60.016 秒，budget_exhausted。
- SolverEngine.step 累计 57.507 秒，约 95.8%；237 次调用中 67 次含实际搜索结果，170 次为计划／选择执行。
- ReplayWorker.restore 累计 1.986 秒，104 次，约 3.3%。
- profile 的 native_search 与 plan_or_selection 只有调用计数；其中 seconds=0 是未单独计时，不能解释为零成本。step 包括原生执行和通信，不是纯求解 CPU 时间。

因此当前证据不支持优先重写存档／恢复机制来提速。该结论只适用于这次短开发测试；不能外推所有深回溯路线。

## 后续优先级

1. 复现并修复 ColorfulPhilosophers 的原生事件兼容问题，保留失败前缀作为回归入口。
2. 用开发集单变量比较常规／Boss 求解预算及计划复用，同时衡量整局成功率、耗血和总墙钟；不能仅凭每次调用加速选择更小预算。
3. 在功能覆盖稳定后比较 1／2／4 lane 及多独立种子并行。成功质量与单机资源争用都需实测。

本轮三个 holdout 的结果现已查看；若据此修改策略或专门修补这些种子，后续最终泛化验收应另设未见保留集。五分钟性能目标保留为未达标，性能测试本身已完成。
