# learn 与迭代驱动：数据供给、训练器、幕组优势、幕组批、裁剪目标

`main/learn/` 与 `main/iterate.py`。设计见 [architecture](../architecture.md#训练路线)。

| 模块 | 内容 |
| --- | --- |
| `loader.py` | 读取进程与打包进程：分片窗口 → 打包好的逻辑批 |
| `trainer.py` | `Learner`：唯一的训练器，对宏动作做加权 NLL（或调用方给的目标）；BC 的轮次与留出；`Learner.load`／`save` 在检查点与训练器之间转换（权重、优化器、日程、`progress` 元数据），`cli` 与 `iterate` 都经它读写检查点 |
| `advantage.py` | 优势文件 `advantages.json.gz` 的读写 |
| `features.py` | 决策帧的状态摘要（幕、楼层、角色、HP、金币、卡组、遗物、药水、是否战斗中），组基线回归用 |
| `groups.py` | 幕组的优势：最后一波 ±1、之前各波取下一波从它存档续打的组均值；共同前缀上的分叉树动作级优势；分叉后的组内岭回归基线 |
| `batches.py` | 幕组批：份额上限后的组权重、各波的份额与一遍的更新次数、每波一路的流（`Joint`） |
| `grpo.py` | 幕组的裁剪目标：温度化策略的裁剪比值加对起点策略的 KL（`Clipped`、`group_update`） |
| `history.py` | 逐更新遥测（`updates.jsonl`）、逐轮汇总（`history.jsonl`）、状态（`status.json`） |
| `../iterate.py` | 迭代驱动：采样 → 优势 → 更新 → 评估 → 清理，可断点续跑 |

## 数据供给

数据量远超内存：同时在内存里的只有几个分片（`--window-shards`），打乱分片顺序和一起读入的样本。`loader_feeders` 个读取进程各持窗口的一部分，各带 `loader_workers` 个 fork 出的打包进程（当前 4 × 6）：一个读取进程解码分片时它的打包进程无事可做，读取进程多于两个才能让各进程的批交替到达。

- 一个打包进程一次准备一个逻辑批：每帧只解析一次；超出预算时按长度从短到长拆成几份，梯度累加后更新一次，所以拆分与进程数都不改变一次更新用到的样本。
- fork 之前 `gc.freeze`，否则子进程里的一次回收会写遍继承来的对象，复制整个窗口。
- 读取进程 fork 时不能有自己的线程（线程持有的锁在子进程里永不释放）：张量按命名共享内存文件传递（torch `file_system` 策略），每个读取进程用自己的管道发消息（`multiprocessing.Queue` 会起写线程）。读取进程与打包进程组成一个进程组，训练进程提前停止时整组结束；强杀残留的共享文件由 `torch_shm_manager` 回收。
- 每个读取进程把窗口末尾不足一批的样本带入下个窗口；结束时主进程收各读取进程至多 B−1 个样本，合并后就地打包。每轮仅最后一批可能不足 B，更新次数为 ceil(N/B)。

## 训练器

`Learner` 只按样本权重求和，权重由供给侧给出（示范的权重规则见 [data](data.md#权重与损失尺度)，幕组的见下）。BC（`bootstrap`）默认持续到手动中断，`--epochs N` 是本次追加的轮数；不设验证、不按表现降学习率或早停。每轮记录 `held_out`、`training`、`samples` 三组计数（留出组没进训练的证据）。正确率是更新前同一次前向里合法动作 Top-1 与标签一致的决策数除以策略决策数，不用样本权重。

`fit(objective=)` 换掉每个宏动作的损失：`objective(learner, prepared, micro)` 返回这一微批每个宏动作的损失、温度 1 下的熵和正确率计数，训练器照旧按样本权重求和、按 `total / B` 缩放、裁剪梯度。

## 幕组的优势

`groups.py`（`advantages(目录)` 给轮里每一波写一份 `advantages.json.gz`：`kind=act-groups`，头里记 `wave`、`boundaries`、`ridge`、统计，正文是每段各决策的（宏动作序号、基线、优势）；已写过的轮直接读回头）：

- 回报：终局通关 +1、死亡 −1；到达边界幕的段取下一波从它那份存档续打的组的回报均值，一波波往前传（第一波的回报是第二波组均值的均值）；下一波没有一条完成的段不给优势，训练时跳过。
- 读分片：每个分片一个任务，`processes` 个进程（默认 8）并行算帧指纹与状态摘要，只把每个决策的（序号、指纹、动作、摘要）传回。
- 分叉树：同一组的段按“到第 k 步为止帧相同”归并，帧的同一性是 `public` 与 `legal` 的指纹。到达者 ≥ 2 的节点上，决策的优势 = 选同一动作者的回报均值 − 节点全部到达者的均值；只有一种动作的节点记 0。动作是宏动作各步所选候选的元组。
- 分叉之后：优势 = (R − 组内均值) − βᵀ(φ − 组内摘要均值)，β 按岭回归（`ridge` 默认 1.0）在组内去均值的数据上拟合，每波分开。文件里的 `value` 就是这个基线（树节点上是节点均值）。
- 头里的 `stats`：组数、段数、决策数、回报均值、组间方差占比（单因素方差分析）、全组同结果的组数、树的节点与覆盖比例、回归的组内 R² 与各特征权重。

## 幕组批

`batches.py`：每一波一路，每个逻辑批按份额从各路取样本（`sizes` 取整后加起来等于批大小）；`priced` 只取有优势的段（到达边界幕而下一波没完成的段没有）。

- **份额权重**（`buffer_weights`，`--phase-weights`）：默认 `group`，一波里按角色×阶段组等权、组内平分，单个决策不超过均匀份额的 `--weight-cap` 倍（默认 10；只出现几次的阶段按上限给，让出的份额分给其余组），这是示范 BC 的阶段平衡规则，战斗占四分之三的决策却只拿到约五分之一的权重；`even` 让每条决策权重相同，是波内的无偏策略梯度。整波之和为 1。
- **份额与权重**（`wave_shares`）。整轮当作一个数据集：一波的组权重乘它占整轮决策数的比例 N_波 / ΣN，训练器按 ΣN / B 缩放，所以一条决策每进一次批的权重都是 1/B，与波无关；它进批的次数由份额定。份额默认按各波有优势的决策数定（`--wave-shares` 给每波一个相对数可改，`1 1 1` 即各波相等），`--updates round` 是 ΣN / B 次更新（`pass_updates`），这时每一路正好走完一遍、每条决策看一次、权重相同，各波对梯度的贡献与决策数成正比。份额大于决策占比的波在一遍里被重复看（每一路用完了重新开始，`Joint`），每次权重不变，所以**一波的份额就是它在梯度里的占比**；等份额时第一幕每条决策的权重约是第三幕的十倍，而第三幕只有一部分样本进过批。
- **读取进程**：每一路有自己的读取进程，profile 的 `loader_feeders` 按各路在批里的份额分给各路（向上取整）、每路至少 2 个（`stream_feeders`；默认份额下第三幕那一路占四分之三的批，4 个读取进程里拿 3 个，实测它只有 2 个时每步等批 8–12%、3 个时 3%），只有一个时它解码下一批分片的间隙整条路停住，联合批跟着等最慢的一路。
- 每个样本按所在的路改记来源，训练器按来源分别报告损失。不留出 seed。更新记录的 `waves.<波>.samples` 是这一遍里该波进批的样本数，`decisions` 是 ΣN。
- 学习率与日程严格续接检查点；`--learning-rates <json>` 给这次运行自己的学习率（[network](network.md#优化器与学习率)）。

## 幕组的裁剪目标

`grpo.group_update(learner, waves, reference, clip=0.2, kl=0.01)`，`iterate` 唯一的更新方式。批见[幕组批](#幕组批)（各波一路、默认按决策数定份额、份额上限后的组权重 × N_波 / ΣN）；每个宏动作的损失：

L = −min(r·A, clip(r, 1 − ε, 1 + ε)·A) + κ·KL

- **优化温度化的策略**。宏动作按它记下的温度 T（`Sample.temperature`）从 π_T 抽出；argmax 与温度无关，greedy 评估不受影响，所以直接把 π_T 当作被优化的策略：r = π_θ,T(a) / π_old,T(a)，π_old,T(a) 是采样时记的 `old_log_prob`。这样更新是同策略的，不需要按 π/π_T 修正权重。宏动作的比值按整个宏动作算（各步之和）；宏动作几乎都只有一个决策。
- **没有信号就不动**。A = 0 的宏动作没有策略梯度：全赢或全输的组不会像加权 BC 那样把策略往它已偏好的动作拉（删掉的优势加权回归就是在这里削尖的，见 [architecture 不采用的做法](../architecture.md#不采用的做法)）。
- **裁剪**。比值在优势推的方向上越过 1 ± ε 后不再推；`clip_fraction` 是裁剪项起作用（A ≠ 0）的比例。对数比值先截在 ±20，防止溢出。
- **KL**。宏动作内各决策在合法动作上的 KL(π_θ,T ‖ π_ref,T) 之和，精确计算；π_ref 默认是 `--checkpoint`（这次运行的起点），`--reference-every k` 时每 k 次迭代换成当时的策略；每次更新载入、同批前向一次、不求导，词表必须与当前策略相同。它抵消自采样的有限样本漂移。
- **不除组内标准差**：回报二值、组小，除标准差会放大 1 胜 3 负这类组。
- **步长**。一轮优势里的可用信号远小于噪声，按 BC 的学习率走一遍，策略会在噪声上漂移（熵升、KL 涨、评估变差）。小学习率（`--learning-rates configs/learning-rates-grpo.json`，BC 的十分之一）配较大的 κ（如 0.1）让一轮用完全部样本、同时把一轮的 KL 压在小量级。
- 熵仍按温度 1 报，`--min-entropy` 照旧适用。

没有监督锚，漂移由 KL 约束。每次更新记 `ratio_mean`、`clip_fraction`、`kl`、`zero_share`（A = 0 的比例）与各波的 `act1_zero_share`、`act1_loss`……；`history.jsonl` 记一遍的均值。

## 迭代驱动

一次迭代（编号 N 从 0 起）：

| 步骤 | 做什么 | 写到 |
| --- | --- | --- |
| `sample` | 一轮幕组（[play](play.md#幕组)），各波依次；被打断的轮（种子相同）从所在的波续跑，不整轮重采；没完成的段按 `--quarantine` 的比例容忍 | `groups/round-N/<波>/`，种子在 `seeds/iteration-NNNN.json` |
| `advantages` | 每波的回报与优势（[幕组的优势](#幕组的优势)），记各波的组数、组间方差占比、树覆盖、组内 R² | `groups/round-N/<波>/advantages.json.gz` |
| `update` | 一遍[裁剪目标](#幕组的裁剪目标)的更新（批见[幕组批](#幕组批)） | `policy/current`、`policy/iteration-NNNN/` |
| `evaluation` | 每 `--evaluate-every`（默认 5）次迭代，用 `--eval-seeds` 每角色前 `--eval-runs-per-character` 个种子 greedy 评估，只写去掉帧的对局文件 | `evaluation/iteration-NNNN/report.json` |
| `cleanup` | 删这次更新之后没有人再读的东西：到这次为止各轮每波的 `accepted/` 分片、`saves/`、`index.jsonl.gz`、`advantages.json.gz`（留 `summary.json`、`quarantine/`）；策略归档只留评估过的（关键存档点）、到期待评估的、下一次更新的 KL 参考和这次的；`interrupted/` 整个删 | 记下释放的空间 |

- 一轮的形状：`--runs-per-character` 是每角色的种子数，`--boundary-acts`（默认 `2 3`）、`--boundary-bosses`（默认无；如 `3` 在第三幕 Boss 入场再切一级，波 `boss3`）、`--group-n`（8）、`--group-m`（8，或每个后续波一个数，波数 = 切点数）。每轮的组不复用。
- `--clip`、`--kl`：[裁剪目标](#幕组的裁剪目标)的 ε 与 κ。`--reference-every k`：KL 的参考每 k 次迭代换成当时的策略（第 N 次迭代用 `policy/iteration-{k·⌊N/k⌋ − 1}`，N < k 用起点检查点），这些归档不被清理，更新记录的 `reference` 记下用的是哪份；默认 0，参考始终是 `--checkpoint`。`--learning-rates <json>` 给这次运行各组的学习率（不给时沿用检查点的），写进这次运行保存的检查点。
- `--config <profile>`：采样温度换成 profile 里的（严格续训时其余设置仍须与检查点一致；给了 `--learning-rates` 时学习率不在比较之列）。
- `--wave-shares`：各波在批里的相对份额，按波的顺序每波一个数；不给时按各波的决策数（见[幕组批](#幕组批)）。`--updates`：`round`（ΣN / B 次，默认）或一个数。
- 采样种子由 `--seed-root` 与迭代号派生（十六位十六进制，每角色等量）；避开 `--exclude-seeds`、`--eval-seeds` 和检查点记下的训练种子，按原样、按游戏读法（O 作 0、I 作 1）和按 `split_group` 三种写法核对。
- 记录：检查点的 `progress` 记迭代号、优势来源（`act-groups`）和这次更新的摘要，`training_seeds` 累积各波的种子；`state.json` 记每次迭代各步的结果与当时的设置；标准输出每完成一步打印一行 JSON。
- 断点续跑：重跑同一条命令（`--iterations` 可加大）。每一步落盘后才记入 `state.json`；被打断的步骤留下的目录移到 `interrupted/` 后重做（这次迭代的清理把它删掉）；策略更新已保存而未记入时不会再更新一次（只认这次运行自己的 `policy/current`，从另一次运行的检查点起步时，那份检查点元数据里的更新不算）。SIGTERM 与 Ctrl+C 一样结束正在进行的步骤，`status.json` 记下停在哪一步。除 `--checkpoint` 与 `--seed-root` 外的设置都可以在两次运行之间改。同一输出目录不能同时被两个进程写。
- 采样、策略更新与裁剪目标的参考前向在同一个进程里轮流用 GPU，每步结束归还显存缓存；全局层是同一个被编译的函数，各步的梯度模式、精度和模块不同，所以驱动放宽编译器对同一函数变体数的上限（`COMPILED_VARIANTS`），否则后出现的运行方式一直不被编译。
- 存储：每次迭代的帧、索引与优势在清理时删除，留下的是各波的摘要；评估几 MB（逐局结果留给配对比较）；策略归档每份约 170 MB，评估过的留下，其余用完即删。

- 采样进程：驱动加载策略后、第一次更新之前 fork 一组（`--workers` 个引擎，`--processes` 个进程），整个运行的各轮采样和评估都用它（`--eval-workers` 不同时，评估另起一组）。每轮结束后它们的引擎退出、进程留下（`Samplers.rest`），训练期只占进程本身（每个约 16 MB）。原因见 [play](play.md#采样进程分工)。

资源（32 引擎、每角色 4–10 种子实测）：采样期采集进程约 1.5–2 GB、32 个采样进程私有内存合计约 1.5–5.7 GB（随段变长而涨；`ps` 的 RSS 含 fork 共享页，每个能显示到 2 GB，不能相加）、32 个引擎 4–6.5 GB；策略更新的加载进程与窗口与 BC 相同、在各路之间平分，合计 4–5 GB 私有内存。

## 遥测

`updates.jsonl` 每次成功更新后写入：损失、正确率、策略熵、裁剪前梯度范数、各组学习率、耗时（`duration_seconds`，从上一步结束算起）与其中阻塞在取批上的秒数（`wait_seconds`，等读取进程的时间；两者之差是训练进程自己的时间）、宏动作数，另有各波的损失与零优势比例、比值均值、裁剪比例、KL。幕组的更新记录与 `history.jsonl` 汇总一遍的等批占比 `update_wait_share`（Σ等批 / Σ耗时）：占比高说明更新阶段卡在读取端。`history.jsonl` 每轮（BC）或每次迭代一行汇总。`status.json` 是最近写入的状态，不能证明进程仍存活。

## 已知的坑

- 分叉之后一段的全部决策共用一个段回报，共享前缀只覆盖很少的决策；单个决策（例如用一瓶药）分到的信用很小。
- 全赢或全输的组里，分叉后的优势只剩岭回归项；它的组内 R² 很小，这部分是噪声，但量级也小。
